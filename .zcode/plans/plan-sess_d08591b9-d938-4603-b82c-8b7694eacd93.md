# Смена ответственного за заявку (helpdesk reassign)

## Контекст

В разделе helpdesk нет UI смены ответственного. Backend-половина **уже есть**:
- `assign_ticket` (`services/helpdesk/tickets.py:429`) явно разрешает реассайн (заменяет предыдущего assignee)
- `POST /tickets/{id}/assign` ставит outbox-запись + вызывает `notify_ticket_assigned`, который уведомляет **инициатора + нового агента** — ровно тех получателей, что просил пользователь
- `enqueue_assigned_email` отправляет email инициатору с ФИО ответственного при настроенном mailbox

Нужно: (1) валидация, что таргет — активный helpdesk-агент (404), (2) агентский endpoint для получения списка активных агентов (для dropdown), (3) фронтенд-UI смены в сайдбаре карточки, (4) i18n, (5) тесты.

## Backend

### 1. Валидация таргета в `/assign`
**Файл:** `backend/app/api/helpdesk/tickets.py` (функция `assign_ticket`, строки 538–580)

Добавить проверку перед `tickets_service.assign_ticket(...)`:
```python
# Таргет должен быть активным helpdesk-агентом (требование: «на любого агента
# тех. поддержки»). Заглушки/удалённые/не-агенты → 404, не раскрываем детали.
from sqlalchemy import select
from app.models.helpdesk import HelpdeskAgent
target = await db.execute(
    select(HelpdeskAgent)
    .join(User, User.id == HelpdeskAgent.user_id)
    .where(HelpdeskAgent.user_id == payload.assignee_user_id, User.deleted_at.is_(None))
)
if target.scalars().one_or_none() is None:
    raise HTTPException(404, "Agent not found")
```

### 2. Агентский endpoint для списка назначаемых агентов

```python
@router.get(
    "/tickets/assignable-agents",
    response_model=AgentOptionListOut,
    summary="Активные агенты для назначения (dropdown)",

async def list_assignable_agents(agent: HelpdeskAgentDep, db: DbDep) -> AgentOptionListOut:
    """Все активные helpdesk-агенты (включая текущего) с живым аккаунтом.
```

Порядок объявления — **до** `/tickets/{id}` (как и `/tickets/counts`), иначе FastAPI свяжет `assignable-agents` как path-param.

## Frontend

```typescript
export interface HelpdeskAgentOption {
  user_id: string

  items: HelpdeskAgentOption[]
  total: number

export function fetchAssignableAgents(): Promise<HelpdeskAgentOptionList> {
  return api<HelpdeskAgentOptionList>('/helpdesk/tickets/assignable-agents')
}
```

### 6. Query mutation
**Файл:** `frontend/src/queries/helpdesk.ts` (extend `useAssignTicketMutation`, который уже есть)

Добавить `useAssignableAgentsQuery` (read-only, ключ `helpdeskKeys.agentsAssignable()`):
```typescript
export function useAssignableAgentsQuery(enabled = true) {
  return useQuery({
    queryKey: ['helpdesk', 'assignable-agents'],
    queryFn: fetchAssignableAgents,
    enabled,
    staleTime: 60_000,  // список агентов меняется редко
  })
}
```
Новый ключ в `keys.ts`: `agentsAssignable: () => ['helpdesk', 'assignable-agents']`.

### 7. UI: popover в `TicketInfoCard`
**Файл:** `frontend/src/components/helpdesk/TicketInfoCard.vue`

Поле «Ответственный» делается кликабельным для агента (новый prop `editable: boolean`, `true` только на странице агента):
- При клике — `n-popover` с `n-select` (filterable, опции — активные агенты)
- Текущий assignee пред-выбран, текущий агент помечен суффиксом «(вы)»
- На выборе «Я» (или на уже текущем) — не делаем мутацию (фронтенд-предфильтр)
- После выбора → `useAssignTicketMutation.mutate(user_id)` → `message.success(t('helpdesk.assigneeChanged'))` + инвалидация `agentTicket(id)` (мутация уже это делает)
- Под inline-формой: при ошибке 404 «Agent not found» → toast и рефетч списка агентов

Для requester-страницы (`HelpdeskMyTicketDetailPage`) — `editable=false`, поведение как раньше (просто показывает ФИО).
