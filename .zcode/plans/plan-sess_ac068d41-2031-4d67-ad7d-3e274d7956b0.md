# План: Поиск пользователей + free-email в блоке «Ответить всем» (CC)

## Контекст и текущее состояние

**Блок «Ответить всем» уже существует** (`TicketReplyForm.vue:9-33`) — `n-checkbox` + `n-select multiple filterable tag`. Но `ccOptions` строится **только из участников тикета** (`participants`). Поиска по всем пользователям портала нет.

**Бэкенд CC полностью готов** (миграция 083): `add_agent_message` принимает `cc: list[str] = Form(default=[])`, нормализует через `_normalize_cc_emails` (strip/dedup/exclude agent+requester/limit 20). Arbitrary emails уже поддерживаются. **Backend CC менять не нужно.**

**Референс** — meetings `ParticipantPicker.vue` (292 строки): remote typeahead + синтетическая «external email» опция. Meetings-specific (i18n namespace `meetings.*`, тип `InvitedUser`, API-вызов `searchParticipants` зашит внутри).

## Решения (согласованы)

1. **UX** — карточки ParticipantPicker (как в meetings): выбранные получатели чипами сверху (имя + email + бейдж «внешний»), инпут remote-поиска снизу.
2. **Endpoint** — новый `GET /api/v1/helpdesk/users/search`, независимый от meetings (gated только `require_helpdesk_module`).
3. **Компонент** — новый `CcRecipientPicker.vue` в `components/helpdesk/` (не обобщать meetings-компонент — у них разные домены/i18n/типы; копирование UX-паттерна чище, чем насильное обобщение).

## Backend

### 1. Schema `backend/app/schemas/helpdesk.py`
Новая лёгкая схема (не `InvitedUser` — тот meetings-принадлежный):
```python
class HelpdeskUserOption(BaseModel):
    """Результат поиска пользователя для CC-селектора агента."""
    user_id: str
    full_name: str
    email: str  # не EmailStr — pydantic EmailStr ломается на .local (AGENTS.md gotcha)
```

### 2. Endpoint `backend/app/api/helpdesk/drafts.py` — НЕ тот файл
Создать **`backend/app/api/helpdesk/users.py`** (НОВЫЙ, по образцу `meetings/participants.py`, но с helpdesk-gate):
```python
router = APIRouter(prefix="/helpdesk", tags=["helpdesk"])  # gate на parent router

@router.get("/users/search", response_model=list[HelpdeskUserOption])
async def search_helpdesk_users(
    user: CurrentUser,
    q: str = Query(min_length=1, max_length=100),
    limit: int = Query(default=20, le=50),
) -> list[HelpdeskUserOption]:
    # min_chars=3 хардкод (как meetings default; helpdesk-настройки для этого нет —
    # не плодить SystemSettings ради одного селектора). <3 символов → пустой список
    # (не 422 — фронт всё равно не покажет опции; 422 ломает n-select empty-state).
    if len(q.strip()) < 3:
        return []
    from app.services.keycloak.directory import search_users
    results = await search_users(q, max_results=limit)
    out = []
    for u in results:
        email = u.get("email")
        if not email:
            continue
        first = u.get("firstName", "") or ""
        last = u.get("lastName", "") or ""
        full_name = f"{first} {last}".strip() or u.get("username", "")
        out.append(HelpdeskUserOption(user_id=u["id"], full_name=full_name, email=email))
    return out
```
**Регистрация:** `helpdesk/__init__.py` → `router.include_router(users_router)`.
**Ошибки Keycloak:** не оборачивать в try/502 здесь (meetings тоже не оборачивает — `search_users` возвращает `[]` при сбое; фронт покажет empty-state). Решение принято после сравнения с `meetings/participants.py` (там нет try/except).

## Frontend

### 3. API `frontend/src/api/helpdesk.ts`
```ts
export interface HelpdeskUserOption {
  user_id: string
  full_name: string
  email: string
}

export function searchHelpdeskUsers(q: string): Promise<HelpdeskUserOption[]> {
  return api<HelpdeskUserOption[]>('/helpdesk/users/search', { params: { q } })
}
```

### 4. Компонент `frontend/src/components/helpdesk/CcRecipientPicker.vue` (НОВЫЙ)
Копия UX-паттерна из `ParticipantPicker.vue`, адаптированная:
- **Тип:** внутренний `CcRecipient = { email, name: string | null, source: 'directory' | 'external' }` (helpdesk-локальный; `name` nullable — у external email имени нет).
- **Props:** `modelValue: CcRecipient[]`, `participants?: HelpdeskParticipant[]` (для pre-fill как «directory» source — они уже в треде).
- **Поиск:** `searchHelpdeskUsers(q)` (debounce 300ms, minChars=3). Дедуп по lowercased email.
- **External option:** синтетическая опция `ext:{email}`, если `EMAIL_RE` матчит и email не среди найденных/выбранных. `renderLabel` с бейджем «внешний».
- **Эмит:** `update:modelValue` с массивом `CcRecipient`.
- **i18n:** новый namespace `helpdesk.cc.*` (`searchPlaceholder`, `externalBadge`, `searchHint`, `invited`, `remove`).

### 5. Интеграция в `TicketReplyForm.vue`
Заменить `n-select` (строки 20-32) на `<CcRecipientPicker>`:
```vue
<CcRecipientPicker
  v-if="replyAll"
  v-model="ccRecipients"
  :participants="participants"
  :disabled="loading"
/>
```
- `ccRecipients: ref<CcRecipient[]>` вместо `ccEmails: ref<string[]>`.
- Pre-fill при включении `replyAll`: участники (минус requester) → `CcRecipient` с `source='directory'`, `name=p.name`.
- На submit: `cc = ccRecipients.value.map(r => r.email)` (конвертация в `string[]` для бэка — контракт `add_agent_message` не меняется).
