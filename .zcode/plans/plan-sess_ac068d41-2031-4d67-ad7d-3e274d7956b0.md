# План: Inline-картинки в форме создания заявки (draft-attachments, «Этап 3»)

## Контекст и решение

**Проблема:** при создании заявки пользователь не может вставить картинку в текст rich-редактора — media-endpoint `POST /tickets/{id}/inline-media` требует `ticket_id`, которого ещё нет (заявка не сохранена). Это UX-асимметрия: в **ответах** на тикет inline-картинки работают, а в **самой заявке** — нет.

**Решение (вариант 1, одобрен):** temporary draft-attachments. Новый endpoint `POST /helpdesk/draft-attachments` (без ticket_id) принимает картинку, хранит её как черновик. При `create_ticket` — backfill: бэк парсит draft-URL'ы в `description_html`, переносит файлы в постоянное хранилище `TKT-{number}/inline/`, переписывает `src` на постоянные inline-media URL. Cron чистит orphan-черновики.

## Архитектурные решения (с обоснованием)

1. **Хранение draft → БД-таблица `helpdesk_draft_attachments`** (не FS-only). Детерминированная ACL через `uploaded_by_user_id`, audit-след, проще дебажить «почему файл пропал/не найден при backfill». URL = `/draft-attachments/{uuid}`.

2. **Постоянное хранилище → `TKT-{number}/inline/`** (унификация с `media.py` ответов). Все inline-картинки тикета (независимо от источника) в одном месте. URL после backfill = `/tickets/{id}/inline-media/{name}` — совпадает с существующим serve-endpoint, меньше спец.логики.

3. **TTL → 24 часа, лимит 20 draft-файлов на юзера.** Баланс: покрывает обед/ночь/выходные, но не копит мусор неделями. Лимит защищает от abuse (старые вытесняются — LRU нет, просто отказ если >20 активных).

## Backend

### 1. Миграция `082_add_helpdesk_draft_attachments.py`
`revision="082"`, `down_revision="081"`. По образцу `080_add_helpdesk_ticket_reads.py` (hand-written SQL, `IF NOT EXISTS`, idempotent).
```sql
CREATE TABLE IF NOT EXISTS helpdesk_draft_attachments (
    id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    uploaded_by_user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    filename           VARCHAR(500) NOT NULL,   -- stored name: {uuid8}_{safe}
    original_name      VARCHAR(500) NOT NULL,
    content_type       VARCHAR(255) NOT NULL,
    size_bytes         BIGINT NOT NULL,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS ix_helpdesk_draft_attachments_user
    ON helpdesk_draft_attachments (uploaded_by_user_id);
CREATE INDEX IF NOT EXISTS ix_helpdesk_draft_attachments_created
    ON helpdesk_draft_attachments (created_at);  -- для cron-cleanup
```
`downgrade`: `DROP TABLE IF EXISTS helpdesk_draft_attachments CASCADE`.

### 2. Модель `backend/app/models/helpdesk.py`
`HelpdeskDraftAttachment` (новый класс), зеркалит колонки миграции. Без relationships (draft — ephemeral, FK только для CASCADE).

### 3. Константы `backend/app/core/constants.py` (блок helpdesk, после строки 23)
```python
HELPDESK_DRAFT_TTL_HOURS = 24      # cron чистит draft-attachments старше этого
```

### 4. Service `backend/app/services/helpdesk/drafts.py` (НОВЫЙ файл)
- `draft_dir(user_id) -> Path`: `HELPDESK_FILES_DIR / "drafts" / f"usr-{user_id}"`.
- `async def create_draft_attachment(db, *, user, file: UploadFile) -> HelpdeskDraftAttachment`: лимит-проверка (`count(*) WHERE uploaded_by_user_id = user.id` < MAX; иначе 409 «слишком много черновиков, удалите лишние»), `_safe_stored_name` (переиспользовать из `attachments.py:64-69`), `stream_upload_to_path` (MIME=HELPDESK_INLINE_IMAGE_MIMES, limit=HELPDESK_MAX_ATTACHMENT_MB), INSERT row, `db.flush()`. Возвращает row с `id` для URL.
- `async def get_draft_for_serve(db, *, draft_id, user_id) -> HelpdeskDraftAttachment`: SELECT + ACL (`uploaded_by_user_id == user_id`, иначе None → 404).
- `async def backfill_draft_images(db, *, ticket, message, html, user) -> str | None`: **ядро backfill'а**. Парсит `<img src>` через существующие `find_img_sources`/`replace_img_src` (`email_images.py:115-126`). Для каждого src, матчащего regex `/api/v1/helpdesk/draft-attachments/([0-9a-f-]{36})`: SELECT draft row (ACL по `user.id`), читает байты, **move** (не copy — draft удалится) в `_ticket_inline_dir(ticket.number)` (переиспользовать из `media.py:49-51`), создаёт `HelpdeskAttachment(is_inline=True, ticket_id, message_id)` через `_build_attachment`-аналог, переписывает src на `/api/v1/helpdesk/tickets/{ticket.id}/inline-media/{stored_name}`, DELETE draft row. Best-effort: битый/отсутствующий draft → src оставляем как есть (не роняем создание заявки). Возвращает обновлённый HTML или None если drafts не было.
- `async def cleanup_expired_drafts(db) -> int`: по образцу `cleanup_archived_files` — `SELECT WHERE created_at < NOW() - TTL`, для каждого `draft_path.unlink()` + `DELETE`, возвращает счётчик. Удаляет пустые `usr-{id}` папки.

### 5. Router `backend/app/api/helpdesk/drafts.py` (НОВЫЙ файл, по образцу `media.py`)
- `POST /helpdesk/draft-attachments` → `create_draft_attachment`, возвращает `MediaUploadResponse(url=f"/api/v1/helpdesk/draft-attachments/{row.id}", filename=row.filename)`. 201. Rate-limit (переиспользовать `RateLimiter(times=20, minutes=1)` — как inline-media).
- `GET /helpdesk/draft-attachments/{draft_id}` → serve через `X-Accel-Redirect` в `/internal/helpdesk-media/drafts/usr-{user_id}/{filename}` (новый nginx location — см. §Infra). ACL: только владелец.
- Регистрация: `helpdesk/__init__.py:24` → `router.include_router(drafts_router)` (после `media_router`).

### 6. Интеграция backfill в `create_ticket`
`backend/app/services/helpdesk/tickets.py:100` — **после** `first_message` flush (есть `ticket.id`, `ticket.number`, `first_message.id`), **до** `_try_enqueue_created_email`:
```python
# Backfill inline-картинок из draft-attachments (если есть в description_html).
# Переносит draft-файлы в TKT-{number}/inline/, переписывает src на постоянные
# inline-media URL. Мутирует ticket.description_html И first_message.body_html.
if payload.description_html:
    new_html = await backfill_draft_images(
        db, ticket=ticket, message=first_message,
        html=payload.description_html, user=user,
    )
    if new_html is not None:
        ticket.description_html = new_html
        first_message.body_html = new_html
```
Оба поля мутируются в той же транзакции (до `db.commit()` в строке 120) — атомарно с созданием тикета.

## Обратно-совместимость
- `POST /tickets` обратно-совместим: если `description_html` не содержит draft-URL (или пуст) — `backfill_draft_images` возвращает None, поведение идентично текущему.
- Старые клиенты без draft-функциональности работают без изменений.
- Миграция zero-downtime (`IF NOT EXISTS`, новая таблица, не трогает существующие).

## Объём и порядок
Это многосессионная задача. Порядок выполнения (зависимости):
1. Миграция + модель + константы (фундамент) — можно закоммитить отдельно.
2. Service `drafts.py` (create + get + backfill + cleanup) + unit-тесты.
3. Router `drafts.py` + регистрация + nginx location.
4. Интеграция backfill в `create_ticket` + integration-тесты.
5. Cron task + регистрация.
6. Frontend (1 файл, минимально) + frontend-тест.
7. Доки + openapi regen.

Каждый этап оставляет код в рабочем состоянии (компилируется, тесты зелёные) — можно коммитить инкрементально.
