# План: Whitelist probe для `/auth/local/login` (обход rate-limiter по доверенной подсети)

## Контекст

Synthetic-проба (cron `run_synthetic_probe`, каждые 5 мин) логинится под `bvs@mage.ru` через настоящий `/auth/local/login`. Но эндпоинт защищён `RateLimiter(times=5, minutes=15)` по IP. Probe приходит с IP screenshot-service (172.18.0.2, подсеть `portal_internal` 172.18.0.0/16). После 5 запросов за 15 мин (probe + ручные вызовы) → **429**. Нужен чистый обход для probe без ослабления brute-force-защиты для реальных пользователей.

Данные с прода:
- screenshot-service: `172.18.0.2` (portal_internal)
- nginx: `172.18.0.9` (portal_internal), probe идёт `screenshot-service → nginx:80 → backend`
- backend видит `X-Real-IP` = IP источника (ставит nginx из `$remote_addr`)
- Подсеть `172.16.0.0/12` уже используется в проекте как «доверенная docker internal» (`nginx/templates/proxy_locations.conf.tmpl`, stub_status allow)

**Почему whitelist по подсети, а не конкретный IP:** IP контейнеров меняются при пересоздании; подсеть стабильна. Подсеть `172.16.0.0/12` (покрывает 172.16–172.31, весь Docker bridge range) — канонический «internal».

**Почему не «сброс Redis-ключей cron'ом»:** флапает между сбросами, хрупко, семантически грязно (борьба с лимитом).

**Почему не отдельный `/probe/login`:** probe должен тестировать **настоящий** путь пользователя end-to-end (иначе не поймает регрессию в `rotate_session`/audit).

## Решение: custom dependency `probe_bypass_rate_limit`

Вместо прямого `Depends(RateLimiter(...))` в `local.py` — обёртка, которая:
- Читает `X-Real-IP` из request (тот же источник, что `real_ip_identifier`)
- Если IP ∈ `172.16.0.0/12` → **no-op** (probe, лимит скипается)
- Иначе → делегирует в `RateLimiter(times=5, minutes=15)` (защита для людей работает)

**Безопасность:** `X-Real-IP` ставит nginx из `$remote_addr` — внешний клиент не может его подделать (зафиксировано в `limiter.py::real_ip_identifier` и AGENTS.md). Атакующий из интернета не имеет IP из docker-подсети.

## Реализация

### 1. `backend/app/core/limiter.py` — хелпер доверенной подсети + bypass-dependency

```python
import ipaddress

# Docker internal bridge-подсети (172.16.0.0/12 покрывает весь default bridge range).
# Запросы отсюда — service-to-service внутри compose-сети; probe-байпас безопасен,
# т.к. X-Real-IP ставит trusted nginx (внешний клиент подделать не может).
TRUSTED_INTERNAL_CIDR = ipaddress.ip_network("172.16.0.0/12")


def is_trusted_internal_ip(ip_str: str) -> bool:
    """IP из docker-internal подсети? (probe, exporters, etc.)"""
    try:
        return ipaddress.ip_address(ip_str) in TRUSTED_INTERNAL_CIDR
    except ValueError:
        return False


def _real_ip(request: Request) -> str:
    """X-Real-IP (от nginx) или request.client.host — единый источник IP."""
    real_ip = request.headers.get("X-Real-IP")
    if not real_ip:
        real_ip = request.client.host if request.client else "unknown"
    return real_ip


def probe_bypass_rate_limit(times: int, minutes: int):
    """Dependency-фабтор: RateLimiter с bypass для доверенных internal-IP.

    Для probe (screenshot-service, IP из 172.16.0.0/12) — лимит скипается.
    Для остальных — стандартный RateLimiter(times, minutes). Заменяет прямой
    Depends(RateLimiter(...)) на эндпоинтах, куда стучится synthetic-проба.
    """
    limiter = RateLimiter(times=times, minutes=minutes)

    async def _dependency(request: Request) -> None:
        if is_trusted_internal_ip(_real_ip(request)):
            return  # probe — пропускаем без счётчика
        await limiter(request, None)  # type: ignore[arg-type]  (Response не нужен для проверки)

    return _dependency
```

NB: `RateLimiter(times=10, ..., identifier=email_identifier)` — **остаётся как есть** (email-лимит на probe не срабатывает: 3 логина/15мин < 10). Байпасим только IP-лимит (5/15min), который и даёт 429.

### 2. `backend/app/api/auth/local.py` — обернуть IP-limiter

```python
# было:
dependencies=[
    Depends(RateLimiter(times=5, minutes=15)),
    Depends(RateLimiter(times=10, minutes=15, identifier=email_identifier)),
],
# стало:
dependencies=[
    Depends(probe_bypass_rate_limit(times=5, minutes=15)),
    Depends(RateLimiter(times=10, minutes=15, identifier=email_identifier)),
],
```

`email_identifier`-лимит не трогаем (probe там укладывается).
