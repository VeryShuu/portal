# План: Rich-редактор (TipTap) при создании заявки helpdesk

## Контекст
`TicketReplyForm.vue` (ответы) уже использует `RichEditor`, а `TicketCreateModal.vue` (создание) — plain `n-input type="textarea"`. Это асимметрия UX. Колонка `description_html` (nullable) уже существует в БД с миграции 075 и сериализуется в `TicketOut`, но `create_ticket` её не заполняет и `POST /tickets` не принимает. Решение — симметрично с `POST /tickets/my/{id}/messages`: принимать опциональное `description_html`, sanitize на бэке, деривировать plain для FTS/email.

Inline-картинки в тексте при создании — НЕ реализуем (курица-яйца: нет `ticket_id` для upload-endpoint); картинки идут как обычные вложения через `n-upload` (текущее поведение). `RichEditor` без `uploadEndpoint` сам показывает warning `editor.imageUploadDisabled` при попытке вставить изображение.

## Backend

### 1. `backend/app/schemas/helpdesk.py::TicketCreateIn`
Добавить поле:
```python
description_html: str | None = Field(default=None, max_length=50000)
```

### 2. `backend/app/api/helpdesk/tickets.py::create_ticket`
- Form-параметр `description` сделать optional с деривацией: `description: str = Form(default="", max_length=20000)` (симметрично `add_my_message` где `body_text` optional).
- Добавить `description_html: str = Form(default="", max_length=50000)`.
- Нормализация через существующий `messages_service.normalize_message_bodies(description, description_html)` (sanitize nh3 + деривация plain из HTML если `description` пуст).
- Валидация «хотя бы что-то есть» через существующий `_validate_message_body` (он уже умеет html-only).
- Передать `TicketCreateIn(description=norm_text, description_html=norm_html)` в сервис.

### 3. `backend/app/services/helpdesk/tickets.py::create_ticket`
- Заполнить `ticket.description_html=payload.description_html` (sanitized).
- Заполнить `first_message.body_html=payload.description_html` — тогда письмо агентам (`render_new_ticket_agent_email`, читает `first_message.body_html`) автоматически получит форматирование без правок email-кода.
- Инвариант `description` (plain) сохраняется — для FTS (`search_tsvector`), email plain-part, список. Существующий тест `test_first_message_invariant` (`first.body_text == ticket.description`) остаётся зелёным.

### 4. `backend/app/services/helpdesk/archive.py::_archive_one` (бесплатный фикс)
Добавить `description_html` в `payload["ticket"]` и `body_html` в message-записи. Иначе rich-описание теряется при архивации (существующая дыра, выявленная при исследовании).

## Frontend

### 5. `frontend/src/components/helpdesk/TicketCreateModal.vue`
- Заменить `<n-input type="textarea">` на `<RichEditor v-model="markdown" :placeholder="...">`.
- **НЕ передавать `uploadEndpoint`** — RichEditor без него блокирует inline-картинки (warning `editor.imageUploadDisabled`), что и нужно при создании (курица-яйца нет `ticket_id`).
- Кнопка submit disabled когда `markdown.trim()` пуст (вместо `description.trim()`).
- На submit: `description = markdown.trim()`, `description_html = md.render(markdown)` (через существующий `mdUnsafe`, как в `TicketReplyForm`). Бэк повторно sanitize'ит nh3 — двойная защита.
- Блок вложений `n-upload` оставить как есть.
- Расширить модал (`max-width: 560px` → `720px`) — rich-редактор с тулбаром требует места.

### 6. `frontend/src/api/helpdesk.ts`
- `HelpdeskTicketCreateDto`: добавить `description_html?: string`.
- `createMyTicket`: `if (dto.description_html) fd.append('description_html', dto.description_html)`.

## Обратно-совместимость
`POST /tickets` остаётся обратно-совместимым: `description` стал optional с деривацией (старые клиенты, шлющие только plain `description`, продолжат работать — `description_html` будет `None`). Миграций БД не требуется — колонка `description_html` уже существует с миграции 075.
