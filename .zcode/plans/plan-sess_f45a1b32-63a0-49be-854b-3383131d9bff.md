## Цель
Отдельный Grafana-дашборд **«Portal — Storage»** (`uid: portal-storage`), показывающий объёмы: БД, папок данных `/data/*`, Redis, Docker json-file логов, Loki chunks, Prometheus TSDB, заполнение ФС. Часть метрик уже скрейпится; для остальных добавляем сбор.

## Изменения — 4 части

### Часть 1. Sidecar-сборщик объёмов (новый контейнер)
**Новые файлы:**
- `monitoring/node-exporter-textfile/Dockerfile` — `FROM alpine:3.20`, ставит `docker-cli` (для имени контейнера по id) или парсит `/host/var/lib/docker/containers/<id>/config.v2.json` через jq/busybox. Копирует скрипт. Запускает busybox `crond -f`.
- `monitoring/node-exporter-textfile/collect.sh` — скрипт сбора. Каждые 5 мин (cron `*/5 * * * *`):
  - **Папки**: `du -sb` по `PORTAL_HOST_PATH/upload_data/{photos/originals,photos/thumbs,photos/zips,kb,feedback,helpdesk,avatars,news_media,branding,link_icons,file-icons}` + `base_data/{postgres,redis}` + `system_data/{settings,secrets,certs,nginx}` → метрика `portal_storage_folder_bytes{folder="..."} <bytes>`.
  - **Docker логи**: итерация по `/host/var/lib/docker/containers/*/` — размер `*-json.log*`, имя сервиса из `config.v2.json` (`jq -r .Name` → strip leading `/`) → `portal_storage_docker_logs_bytes{service="backend|nginx|..."} <bytes>`.
  - Пишет атомарно (`> tmp && mv tmp /textfile/storage.prom`), метрики с `# HELP/TYPE`.
- `monitoring/node-exporter-textfile/crontab` — `*/5 * * * * /usr/local/bin/collect.sh`.

**Правка `monitoring/docker-compose.monitoring.yml`:**
- Новый сервис `storage-collector` (alpine, `restart: unless-stopped`, `security_opt: no-new-privileges`, mount `/:/host:ro`, mount `./monitoring/textfile:/textfile`, env `PORTAL_HOST_PATH=/home/snow/portal`, `logging: *default-logging`, networks `internal`). Порт наружу не торчит.
- `node-exporter`: добавить в `command` `--collector.textfile --collector.textfile.directory=/textfile`, добавить volume `./monitoring/textfile:/textfile:ro`.
- Создать директорию `monitoring/textfile/` (с `.gitkeep`, т.к. пустая директория не коммитится; скрипт пишет `.prom` сюда).

### Часть 2. Loki scrape-job
**Правка `monitoring/prometheus.yml`:** добавить job `loki` → `loki:3100/metrics`, label `service: loki`. Даст `loki_distributor_bytes_received_total`, `loki_chunks_store_index_size_bytes`, и др. для панелей объёма логов.

### Часть 3. Дашборд `monitoring/grafana/portal-storage.json`
uid `portal-storage`, title `Portal — Storage`, tags `["portal","storage"]`, datasource `{"type":"prometheus","uid":"prometheus"}` hardcode, refresh `30s`, time `now-6h→now`, schemaVersion 39, `graphTooltip:1`. Ссылка в `links` на `Portal — Infrastructure` (`/d/portal-infra/portal-infrastructure`).

**Ряды (5):**

**Row 1 — PostgreSQL**
- P1 (timeseries, 24×8): Размер БД — `pg_database_size_bytes`, legend `{{ datname }}`, unit bytes.
- P2 (table, 24×8): Топ-10 таблиц по размеру — `topk(10, pg_table_size_bytes)`, unit bytes, сортировка по значению.

**Row 2 — Redis**
- P3 (stat, 8×6): Память — `redis_memory_used_bytes`, unit bytes.
- P4 (stat, 8×6): Ключи — `sum(redis_db_keys)`, unit short.

**Row 3 — Папки данных `/data/*`** ← текстовые метрики из sidecar
- P5 (timeseries, 24×8): Папки данных по размеру — `portal_storage_folder_bytes`, legend `{{ folder }}`, unit bytes.
- P6 (stat panel / top, 12×8): Топ-5 папок (текущий размер) — `topk(5, portal_storage_folder_bytes)`, unit bytes.
- P7 (piechart, 12×8): Распределение по папкам — `portal_storage_folder_bytes`, label `{{ folder }}`.

**Row 4 — Логи на диске** (Docker json-file + Loki)
- P8 (timeseries, 24×8): Объём Docker-логов по сервисам — `portal_storage_docker_logs_bytes`, legend `{{ service }}`, unit bytes. Пороги: warn 200MB (200000000), red 240MB (cap 250MB).
- P9 (timeseries, 12×8): Loki — принято байт — `rate(loki_distributor_bytes_received_total[5m])`, unit Bps.
- P10 (stat, 12×6): Loki — объём chunks на диске — `loki_chunks_store_index_size_bytes` (или аналог; уточню по доступным метрикам после добавления scrape).

**Row 5 — ФС и TSDB**
- P11 (timeseries, 24×8): Заполнение ФС по mountpoints — `1 - (node_filesystem_avail_bytes / clamp_min(node_filesystem_size_bytes,1))`, legend `{{ mountpoint }}`, unit percentunit, пороги warn 0.80 / red 0.85 (как в infra).
- P12 (timeseries, 12×8): Свободно bytes — `node_filesystem_avail_bytes{mountpoint!~"/(dev|proc|sys).*"}`, unit bytes.
- P13 (timeseries, 12×8): Prometheus TSDB — `prometheus_tsdb_storage_blocks_bytes` vs лимит `prometheus_tsdb_retention_limit_bytes` (two targets), unit bytes.

## Запуск/проверка после реализации
1. `docker compose -f docker-compose.yml -f monitoring/docker-compose.monitoring.yml build storage-collector node-exporter`
2. `docker compose -f docker-compose.yml -f monitoring/docker-compose.monitoring.yml up -d storage-collector node-exporter prometheus grafana`
3. Проверить: `curl -s localhost:9100/metrics | grep portal_storage` (должны быть папки + docker-логи)
4. Открыть Grafana `:3001` → дашборд «Portal — Storage»
