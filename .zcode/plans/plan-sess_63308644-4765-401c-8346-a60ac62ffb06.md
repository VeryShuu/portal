## ЗАДАЧА 1 — Чиним integration-тест (блокер)

**Файл:** `backend/tests/integration/test_rate_limit_matrix.py`

**Причина:** В CI FastAPI 0.139.2 (пин `<0.140.0`), локально 0.136.3. С 0.137+ `include_router` создаёт `_IncludedRouter`-обёртки (PR fastapi#15785); discovery-функция `_iter_api_routes` спускается в `original_router.routes` и **теряет parent-prefix** (тот, что в `include_router(sub, prefix="/news")`). Лист-маршруты news/photos отдаются с путями без `/news`, `/photos` → запросы идут на несуществующие пути → 404 вместо 429.

**Фикс (version-agnostic):**
1. Guard-import `iter_route_contexts` из `fastapi.routing` (публичный API с 0.137+, возвращает `RouteContext` с полным `.path` и `.dependant`).
2. В `_discover_rate_limited_routes`:
   - Если `iter_route_contexts` доступен (0.137+) — обходим его, у каждого контекста берём `.route` (для поиска RateLimiter в `dependant.dependencies`) и `.path` (полный, со всеми prefix'ами). Возвращаем `(method, full_path, times)`.
   - Если нет (0.136 и ниже) — старый flatten-обход `_iter_api_routes` работает как есть (`route.path` уже полный, `_IncludedRouter` не создаётся).
3. Удалить ставший ненужным duck-typing спуск в `original_router.routes` (или оставить как fallback-комментарий).

**Дополнительно:** `test_discovery_finds_known_endpoints` (строки 147-149) — false-green (ищет только leaf-prefix эндпоинты). Добавить в assertions проверку `/news/` и `/photos/` фрагментов, чтобы sanity-чек ловил ту же регрессию, что и матрица.

**Верификация (обязательно — локальный FastAPI отличается от CI):**
1. Локально (0.136.3): `cd backend && pytest tests/integration/test_rate_limit_matrix.py -x` — fallback-path должен пройти.
2. В CI-окружении (`.venv-ci` с fastapi 0.139.2): создать изоляцию и прогнать там. Если `.venv-ci` уже есть от `ci_lint.sh` — использовать его. Иначе поднять temp-venv `pip install -e ".[dev]"` и прогнать. Это единственный способ получить достоверный сигнал до пуша (урок 2026-07-24 из AGENTS.md).
