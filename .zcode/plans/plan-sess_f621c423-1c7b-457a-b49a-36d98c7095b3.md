## P1 — KB/directories PDF export падает на ошибках screenshot-service

### Корень
1. **Неперехваченный `HTTPStatusError`:** ручка `export_article_pdf` (`backend/app/api/kb/export_import.py:274`) и `export_entries` (`backend/app/api/directories.py:362`) зовут `render_pdf()` без try/except. Внутри `render_pdf` (`backend/app/core/pdf.py:30`) — `resp.raise_for_status()` кидает `httpx.HTTPStatusError` (400/413 от screenshot-service), который пробрасывается наружу → 500 + `Exception in ASGI application`.
2. **Почему 413:** `screenshot-service/main.py:496` создаёт `web.Application()` без `client_max_size` → aiohttp-дефолт **1 МБ**. Большая KB-статья (HTML с inlined base64-медиа) превышает лимит → 413.
3. **News-ручка уже обёрнута** (`news/export.py:290-304` → 503) — потому её в логах нет. KB и directories — нет.

### Решение

**A. Обёртка ручек (использует существующий эталон из news/export.py):**
- `kb/export_import.py:272-274` — обернуть `render_pdf(...)` в try/except по образцу `news/export.py`: catch `Exception` → `logger.exception("kb.pdf_render_failed", ...)` → `raise HTTPException(503, "PDF generation failed")`.
- `directories.py:360-364` — то же самое (логировать `directories.pdf_render_failed`).
- В обе ручки нужен `from app.core.logging import get_logger` + `logger = get_logger(__name__)` (проверить наличие по месту; в directories импорт `render_pdf` уже есть сверху).

**B. Лимит body screenshot-service (фикс 413 на корне):**
- `screenshot-service/main.py`: добавить env `PDF_MAX_BODY_MB` (конвенция сервиса — UPPERCASE, парсинг при импорте, как `MAX_WIDTH`/`PAGE_TIMEOUT_MS`), дефолт `16`, парсить → байты.
- `build_app()` (`main.py:496`): `web.Application(client_max_size=PDF_MAX_BODY_BYTES)`.
- `docker-compose.yml:86-93` (env блока screenshot-service): добавить `PDF_MAX_BODY_MB=${PDF_MAX_BODY_MB:-16}`.
- `.env.example`: продокументировать рядом с `SCREENSHOT_*` (~строка 80-84).
- Это убирает 413 для типичных больших статей; 16 МБ с запасом (KB-медиа до 20 МБ, но в PDF уходит в уменьшенных data-URI).

### Тесты (P1)
- `backend/tests/unit/test_kb_export_import.py`: добавить кейс `test_export_pdf_503_on_render_failure` — `render_pdf` мок брасает `httpx.HTTPStatusError("413...")` → ручка возвращает **503**, не 500/ASGI. По образцу существующих моков `patch("app.core.pdf.render_pdf", ...)` (стр. 850).
- `backend/tests/unit/test_directories_service.py` (или `test_staff_directory.py` — уточнить где `export_entries`): кейс `fmt=pdf` + `render_pdf` raises → 503.
- Тест screenshot-service: отдельного unit-сета нет (Python-сервис вне backend venv). Документирую через то, что `build_app()` принимает/читает env; smoke-проверка вручную через `PDF_MAX_BODY_MB=… python -c "import main; assert main.build_app()._client_max_size"` — если это тривиально, добавлю мини-тест, иначе ограничусь ручной проверкой и фиксирую в DoD.

## Chore — приглушить шум helpdesk-poll

### Корень
1. `ingress.py:212` пишет `helpdesk.ingress.poll_done` на INFO каждый poll (~каждую минуту), даже когда `fetched=0, errors=0` — чистый шум в prod-логах.
2. ARQ worker пишет дублирующую финишную строку `0.07s ← cron:...poll_helpdesk_mailbox ● {...}`. Фильтр `QuietCronFilter` (`_arq_log_filter.py`) уже глушит такие строки для audit/email_outbox/metrics-cron, но **helpdesk-poll не в списке** `QUIET_CRON_REFS`. `log_results=False` не подавляет саму строку (только result-repr) — проверено.

### Решение
**A. No-op гейт в ingress:**
- `ingress.py:212` — понижать до DEBUG, когда поллинг пуст (`fetched == 0 and errors == 0`). Иначе — INFO. Реальный результат (есть письма / есть ошибки) остаётся видимым на INFO. Это устраняет ~95% строк (ящик обычно пуст).

**B. ARQ-дубликат:**
- `_arq_log_filter.py` — добавить `"cron:app.worker.tasks.helpdesk.poll_helpdesk_mailbox"` в `QUIET_CRON_REFS`. Фильтр гасит только старт/финиш-строки (маркеры `→`/`←`), **пропуская** ошибки (`! failed`), ретраи (`↻`) и WARNING+. Чувствительные события не теряются.

### Тесты (Chore)
- `tests/unit/test_arq_log_filter.py` — кейс `test_helpdesk_poll_cron_filtered`: старт/финиш helpdesk-poll гасятся (`assert f.filter(...) is False`). Тесты уже параметризованы по `QUIET_CRON_REFS`, так что новый ref автоматически покрывается существующими `test_quiet_cron_start_filtered`/`test_quiet_cron_end_filtered` — добавлю отдельный явный кейс для документируемости + удостоверюсь, что error-строка helpdesk-poll остаётся видна.
- helpdesk-ingress no-op гейт: проверить существующий `test_helpdesk_worker_poll.py` — есть ли там ассерт на `poll_done`-лог; если есть, скорректировать ожидание уровня. Если нет — добавить кейс `test_poll_done_debug_when_noop`.
