## 1. Hard-limit на размер картинки при PDF-экспорте

**Файл:** `./backend/app/api/news/export.py:178-194` (функция `_load_export_media`)

### Простыми словами

При экспорте новости в PDF cover-картинка и картинки галереи кодируются в base64 и вшиваются прямо в HTML. Кодирование уже выполняется в отдельном потоке (event loop не блокируется), но **нет проверки на размер исходного файла**. Если редактор загрузит cover на 50 МБ — поток будет занят 5–10 секунд, итоговый PDF раздуется до 70+ МБ, скачивание займёт минуты.

### Что в коде сейчас

```python
cover_uri = await asyncio.to_thread(to_uri, NEWS_MEDIA_DIR / news.cover_image)
```

Никакой проверки `os.path.getsize(...)` перед кодированием.

### Что нужно сделать

1. Добавить константу `MAX_EXPORT_IMG_BYTES = 10 * 1024 * 1024` (10 МБ).
2. Перед `asyncio.to_thread(to_uri, path)` — проверить размер; если больше — пропустить (cover_uri = None / placeholder).
3. Залогировать `news.export.image_skipped_too_large` для аудита.
4. Unit-тест: `test_export_skips_oversized_cover`.

### Оценка

- **Сложность:** низкая (~20 строк кода + 1 тест).
- **Опасность бездействия:** низкая. Нужно, чтобы редактор реально загрузил гигантскую картинку как cover, а пользователи запросили экспорт. На текущем масштабе портала маловероятно.
- **Опасность hardening'а:** нулевая.

## 2. Health-check наличия `libmagic` при старте

**Файл:** `./backend/app/core/uploads.py:21-24`

### Простыми словами

Реальная проверка типа загружаемых файлов (картинка/exe-файл/PDF) делается через системную библиотеку `libmagic`. В коде она импортируется в `try/except`: если библиотеки нет в контейнере — портал **молча** переходит на менее надёжную проверку (доверять заголовку браузера, который легко подделать).

Угроза: если кто-то соберёт Docker-образ без `libmagic-dev`, проверка типов деградирует, и никто не заметит, пока не произойдёт инцидент.

### Что в коде сейчас

```python
try:
    import magic
except Exception:
    magic = None  # silent fallback
```

### Что нужно сделать

1. В `./backend/app/main.py` (lifespan startup) добавить проверку:
   ```python
   from app.core.uploads import magic as _magic
   if _magic is None:
       logger.error("startup.libmagic_missing")
       # либо raise RuntimeError, либо отметить в health-endpoint
   ```
2. В `/healthz` отразить статус (например `mime_detection: "magic" | "fallback"`).
3. Опционально — флаг настройки `require_libmagic: bool = True` для prod.

### Оценка

- **Сложность:** низкая (~15 строк).
- **Опасность бездействия:** низкая–средняя. Зависит от дисциплины сборки Docker-образа. Сейчас Dockerfile корректный — но регрессия возможна.
- **Опасность hardening'а:** нулевая.

## 3. Расширение XSS-тест-сьюта bypass-векторами

**Файл:** `./backend/tests/security/test_xss_sanitization.py` (86 LOC)

### Простыми словами

Санитизация HTML в теле новости работает на библиотеке `nh3` (Rust-биндинг ammonia — индустриальный стандарт). Это надёжно, но текущий тест-сьют проверяет только базовые случаи (`<script>`, `<iframe>`, `onclick`). За пределами allowlist остаются менее очевидные векторы атаки — стоит добавить негативные тесты для них как защиту от регрессий.

### Что нужно сделать

Добавить тесты на следующие классы payload'ов:

1. **SVG-payload**: `<svg><script>alert(1)</script></svg>`, `<svg onload=alert(1)>`.
2. **MathML**: `<math><mtext><script>alert(1)</script></mtext></math>`.
3. **Polyglot HTML/JS**: `<img src=x onerror=alert(1)>`, `<a href="javascript:void(0)">`.
4. **CSS-injection через style**: `style="background:url(javascript:alert(1))"` (сейчас только text-align проходит — нужен явный тест на это).
5. **HTML-комментарии с условным выполнением (IE legacy)**: `<!--[if IE]><script>alert(1)</script><![endif]-->`.
6. **Mutation XSS**: payload, безопасный в одном парсере и опасный после reparse'инга на фронте.

Цель — не «найти баги в nh3» (их там нет), а **зафиксировать поведение** как контракт: любая будущая правка allowlist'а должна не сломать эти тесты.

### Оценка

- **Сложность:** средняя (~80–120 строк тестов, ~1 человеко-день включая ресёрч известных векторов).
- **Опасность бездействия:** низкая. Реальной защиты `nh3` достаточно. Это страховка от человеческой ошибки при правке allowlist'а.
- **Опасность hardening'а:** нулевая.
