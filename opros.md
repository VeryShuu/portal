# ТЗ: Опросы как часть новости

## 1. Контекст и подход

Опрос — это **компонент новости** (по аналогии с галереей `NewsGalleryImage` и вложениями `NewsAttachment`). Не самостоятельная сущность в ленте, не отдельный виджет. Одна новость может содержать **0..1 опрос**.

Ключевые принципы:
- Новость остаётся «контейнером» контента: текст + обложка + галерея + вложения + **опрос**.
- Жизненный цикл опроса связан с новостью (CASCADE при удалении), но имеет собственный статус (`open` / `closed`) и собственный `closes_at`.
- Голосование — отдельная подсистема со своими правами и эндпоинтами.

## 2. Анализ лучших практик

### 2.1. Функциональные возможности
Полноценный опрос должен поддерживать:

1. **Типы голосования**:
   - Single choice — один вариант из N.
   - Multiple choice — несколько вариантов, с ограничением `max_choices` (опционально).

2. **Анонимность**:
   - `is_anonymous = true` — результаты показывают только агрегаты, никто не видит, кто как голосовал.
   - `is_anonymous = false` — можно посмотреть список проголосовавших по каждому варианту (с учётом прав).
   - Защита от повторного голосования работает в обоих режимах (через `user_id`, но не показываем связь).

3. **Сроки**:
   - `closes_at` — опциональная дата закрытия. Если `null` — опрос бессрочный.
   - Закрытие может быть автоматическим (по `closes_at`) и ручным (автор/админ).
   - После закрытия — только просмотр результатов, голосование запрещено.

4. **Видимость результатов**:
   - `results_visibility`:
     - `always` — результаты видны всем всегда.
     - `after_vote` — результаты видны только после голосования пользователя.
     - `after_close` — результаты видны только после закрытия опроса.
     - `only_admin_editor` — результаты видны только администраторам и редакторам (пользователи видят только варианты для голосования, без счётчиков и процентов даже после своего голоса или закрытия).

5. **Изменение голоса**:
   - `allow_revote` — можно ли менять свой голос до закрытия опроса. По умолчанию `false`.

6. **Редактирование опроса**:
   - До первого голоса — можно менять вопрос, варианты, настройки.
   - После первого голоса — можно менять только `closes_at` (продление/сокращение), название вопроса и текст вариантов (без добавления/удаления вариантов).
   - Удалить опрос можно всегда (вместе с голосами), но это требует подтверждения.

7. **Варианты ответов**:
   - От 2 до 20 вариантов.
   - Длина текста варианта — до 200 символов (может быть пустым или играть роль подписи, если прикреплено изображение).
   - Порядок сохраняется через `sort_order`.
   - **Голосование за картинку / визуальный опрос**: каждый вариант может содержать необязательное изображение (`image_url`). При рендеринге такие варианты отображаются в виде плитки/галереи картинок с крупными тач-зонами.

8. **Защита от накруток**:
   - Один голос на пользователя (`UNIQUE(poll_id, user_id)` для single; `UNIQUE(option_id, user_id)` для multiple).
   - Голосование требует аутентификации.
   - Rate-limit на эндпоинт голосования.

### 2.2. UX-практики
- Показывать счётчик голосов и процент по каждому варианту.
- Подсвечивать выбранный пользователем вариант.
- Показывать общее число проголосовавших.
- Показывать оставшееся время до закрытия (если есть `closes_at`).
- Для неавторизованного — призыв войти, чтобы проголосовать.
- Кнопка «Изменить голос» / «Отменить голос» — если `allow_revote = true`.
- После закрытия — явный бейдж «Опрос завершён».
- На мобильных — крупные тач-зоны для выбора варианта.

### 2.3. Доступность (a11y)
- Использовать нативные `<input type="radio">` / `<input type="checkbox">` в `<fieldset>` с `<legend>` = вопрос.
- ARIA-атрибуты для прогресс-баров результатов (`role="progressbar"`, `aria-valuenow`, `aria-valuemax`).
- Поддержка клавиатурной навигации.

### 2.4. Производительность
- Агрегаты (count по вариантам) считаются по запросу с индексом на `option_id`.
- Опционально — денормализованный счётчик `PollOption.votes_count` для горячих опросов (обновляется триггером или в сервисе).
- Один JOIN-запрос для получения новости с опросом и агрегатами.

## 3. Модель данных

### 3.1. Таблица `news_polls`
Хранит сам опрос. FK на новость, `ON DELETE CASCADE`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | |
| `news_id` | UUID FK -> `news.id` ON DELETE CASCADE, UNIQUE | Один опрос на новость |
| `question` | VARCHAR(500) NOT NULL | Текст вопроса |
| `is_multiple` | BOOLEAN NOT NULL DEFAULT false | Можно ли выбрать несколько вариантов |
| `max_choices` | INTEGER NULL | Ограничение для multiple (NULL = без лимита) |
| `is_anonymous` | BOOLEAN NOT NULL DEFAULT true | |
| `allow_revote` | BOOLEAN NOT NULL DEFAULT false | |
| `results_visibility` | VARCHAR(20) NOT NULL DEFAULT 'after_vote' | `always` / `after_vote` / `after_close` / `only_admin_editor` |
| `closes_at` | TIMESTAMPTZ NULL | Когда автоматически закрыть |
| `closed_at` | TIMESTAMPTZ NULL | Когда фактически закрыт (заполняется автоматически или вручную) |
| `created_at` | TIMESTAMPTZ NOT NULL DEFAULT NOW() | |
| `updated_at` | TIMESTAMPTZ NOT NULL DEFAULT NOW() | |

CHECK: `results_visibility IN ('always','after_vote','after_close','only_admin_editor')`
CHECK: `max_choices IS NULL OR (is_multiple = true AND max_choices >= 1)`

### 3.2. Таблица `news_poll_options`
| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | |
| `poll_id` | UUID FK -> `news_polls.id` ON DELETE CASCADE | |
| `text` | VARCHAR(200) NULL | Текст варианта (может быть NULL, если задан `image_url`) |
| `image_url` | VARCHAR(500) NULL | URL/путь к картинке (для голосования за картинку) |
| `sort_order` | INTEGER NOT NULL DEFAULT 0 | |
| `created_at` | TIMESTAMPTZ NOT NULL DEFAULT NOW() | |

CHECK: `text IS NOT NULL OR image_url IS NOT NULL`

Индекс: `idx_poll_options_poll_id_sort (poll_id, sort_order)`

### 3.3. Таблица `news_poll_votes`
| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | |
| `poll_id` | UUID FK -> `news_polls.id` ON DELETE CASCADE | Денормализация для быстрой проверки и удаления |
| `option_id` | UUID FK -> `news_poll_options.id` ON DELETE CASCADE | |
| `user_id` | UUID FK -> `users.id` ON DELETE CASCADE | |
| `created_at` | TIMESTAMPTZ NOT NULL DEFAULT NOW() | |

Ограничения:
- UNIQUE `(option_id, user_id)` — пользователь не голосует за один вариант дважды.
- UNIQUE `(poll_id, user_id)` — **только если `is_multiple = false`**. В Postgres это можно реализовать частичным индексом или проверкой на уровне приложения (плюс транзакция с advisory lock).
- Индекс `(poll_id, option_id)` для агрегатов.
- Индекс `(user_id)` для запроса «как я голосовал».

## 4. Backend API

Базовый префикс: `/api/news/{news_id}/poll`

### 4.1. Управление опросом (только автор новости / редактор / админ)

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/news/{news_id}/poll` | Создать опрос для новости |
| `GET` | `/api/news/{news_id}/poll` | Получить опрос (вместе с агрегатами и моим голосом) |
| `PATCH` | `/api/news/{news_id}/poll` | Обновить настройки/вопрос/варианты (правила из 2.1.6) |
| `DELETE` | `/api/news/{news_id}/poll` | Удалить опрос целиком |
| `POST` | `/api/news/{news_id}/poll/close` | Принудительно закрыть |
| `POST` | `/api/news/{news_id}/poll/reopen` | Переоткрыть (только если `closes_at` ещё не наступил) |

### 4.2. Голосование (любой аутентифицированный пользователь, имеющий доступ к новости)

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/news/{news_id}/poll/vote` | Body: `{ option_ids: [uuid, ...] }`. Создаёт голос(а) |
| `DELETE` | `/api/news/{news_id}/poll/vote` | Отозвать свой голос (если `allow_revote`) |

### 4.3. Формат ответа `GET /api/news/{news_id}/poll`

```json
{
  "id": "uuid",
  "news_id": "uuid",
  "question": "Какой день недели лучший?",
  "is_multiple": false,
  "max_choices": null,
  "is_anonymous": true,
  "allow_revote": false,
  "results_visibility": "after_vote",
  "closes_at": "2026-06-01T12:00:00Z",
  "closed_at": null,
  "is_closed": false,
  "total_voters": 42,
  "options": [
    {
      "id": "uuid",
      "text": "Пятница",
      "sort_order": 0,
      "votes_count": 30,
      "votes_percent": 71.4
    }
  ],
  "my_vote": {
    "option_ids": ["uuid"],
    "voted_at": "2026-05-20T10:00:00Z"
  },
  "can_vote": true,
  "can_see_results": true
}
```

Поля `votes_count`, `votes_percent`, `total_voters` отдаются только если `can_see_results = true`. Иначе — `null` или скрываются.

### 4.4. Коды ошибок

| Код | Случай |
|---|---|
| 400 | Невалидные данные (пустой вопрос, <2 вариантов, варианты дубли) |
| 401 | Неаутентифицирован при попытке голоса |
| 403 | Нет прав на новость/опрос; попытка править после голосов |
| 404 | Опрос/новость не найдены |
| 409 | Уже проголосовал и `allow_revote=false`; опрос закрыт; превышен `max_choices` |
| 422 | option_id не принадлежит этому опросу |

### 4.5. Бизнес-правила
1. Создать опрос можно только для новости, к которой у пользователя есть права на редактирование.
2. Минимум 2 варианта, максимум 20.
3. Варианты с одинаковым текстом запрещены.
4. При `is_multiple=false` — `option_ids` ровно из 1 элемента.
5. При `is_multiple=true` — от 1 до `max_choices` (или без лимита) элементов.
6. Если `closes_at <= NOW()` — опрос автоматически считается закрытым (фоновая задача проставляет `closed_at`).
7. Транзакционность: голосование выполняется в транзакции с advisory lock на `(poll_id, user_id)`.

## 5. Frontend

### 5.1. Компонент `<NewsPoll />`
Рендерится внутри страницы новости после тела (или в позиции, заданной редактором).

Состояния:
- **Загрузка** — skeleton.
- **Не голосовал, опрос открыт** — список вариантов + кнопка «Проголосовать» (disabled пока ничего не выбрано).
- **Проголосовал** — варианты с прогресс-барами; подсветка моего выбора; кнопка «Изменить голос» (если `allow_revote`).
- **Опрос закрыт** — список с результатами + бейдж «Завершён».
- **Нет прав видеть результаты** — варианты без процентов, надпись «Результаты будут видны после ...».
- **Неавторизован** — варианты + CTA «Войдите, чтобы проголосовать».

### 5.2. Редактор опроса в форме новости
- В форме создания/редактирования новости — секция «Опрос» (collapsible, по умолчанию свёрнута).
- Кнопка «Добавить опрос» → раскрывает форму:
  - Вопрос (input).
  - Список вариантов (drag-and-drop сортировка, кнопки «+ Добавить вариант» и «×»).
  - Чекбокс «Можно выбрать несколько».
  - Поле `max_choices` (если включено multiple).
  - Чекбокс «Анонимный опрос».
  - Чекбокс «Разрешить менять голос».
  - Select «Когда показывать результаты».
  - DateTime picker «Закрыть автоматически» (опционально).
- Кнопка «Удалить опрос» — с подтверждением (если уже есть голоса — предупреждение).

### 5.3. Список новостей (лента)
- Если у новости есть активный опрос — небольшой бейдж/иконка «Опрос» на карточке.
- Сам опрос на карточке не рендерится (только на детальной странице), чтобы не загромождать ленту.

### 5.4. Уведомления (опционально, фаза 2)
- Уведомление автору при первом голосовании / при закрытии опроса.
- Подписка пользователя «уведомить о результатах» — при закрытии опроса.

## 6. Права доступа (Roles matrix)

| Действие | Аноним | Пользователь | Автор новости | Редактор | Админ |
|---|---|---|---|---|---|
| Видеть опрос | ✓ (если новость публична) | ✓ | ✓ | ✓ | ✓ |
| Голосовать | ✗ | ✓ | ✓ | ✓ | ✓ |
| Видеть результаты | по правилам `results_visibility` | по правилам (в режиме `only_admin_editor` доступ закрыт) | ✓ всегда | ✓ всегда | ✓ всегда |
| Создать/изменить/удалить опрос | ✗ | ✗ | ✓ (своя новость) | ✓ | ✓ |
| Принудительно закрыть | ✗ | ✗ | ✓ | ✓ | ✓ |
| Видеть список проголосовавших | ✗ | только если `is_anonymous=false` | ✓ | ✓ | ✓ |

## 7. Миграции

Создать одну Alembic-миграцию `add_news_polls`:
1. Таблица `news_polls` с констреинтом на `results_visibility IN ('always','after_vote','after_close','only_admin_editor')`.
2. Таблица `news_poll_options` с опциональным полем `image_url` и CHECK-констреинтом `text IS NOT NULL OR image_url IS NOT NULL`.
3. Таблица `news_poll_votes`.
4. Индексы из раздела 3.
5. Частичный UNIQUE-индекс для single-choice (через `CREATE UNIQUE INDEX ... WHERE ...`).

Downgrade: `DROP TABLE` в обратном порядке.

## 8. Тесты

### 8.1. Backend (pytest)
- Создание опроса: успех, валидация (мало вариантов, дубли, длинный текст).
- Редактирование до/после первого голоса.
- Голосование: single, multiple, повторное (запрет/разрешение), за чужой вариант (422), в закрытый опрос (409).
- Закрытие: ручное, автоматическое по `closes_at`.
- Видимость результатов в трёх режимах.
- Анонимность: при `is_anonymous=true` API не отдаёт `user_id` в голосах.
- Каскадное удаление: удаление новости удаляет опрос и голоса.
- Race condition: два одновременных голоса от одного юзера → один успешен, второй 409.
- Права: чужой пользователь не может править/удалять/закрывать опрос.

### 8.2. Frontend (Vitest + Playwright)
- Рендер компонента в каждом из состояний (5.1).
- Голосование, отмена голоса, изменение голоса.
- Редактор: добавление/удаление/сортировка вариантов, валидация формы.
- E2E: создать новость с опросом → проголосовать с другого пользователя → проверить агрегаты.

## 11. Технические рекомендации и дополнения

1. **Реализация ограничения уникальности голосов**:
   - Так как частичный уникальный индекс на `news_poll_votes` по условию `is_multiple = false` не может ссылаться на колонку из связанной таблицы `news_polls`, рекомендуется на уровне базы данных реализовать схему с двумя таблицами:
     - `news_poll_voters` (для хранения факта голосования с ограничением `UNIQUE(poll_id, user_id)`).
     - `news_poll_votes` (для связи `voter_id` и `option_id`). В случае `is_multiple = false` на уровне API/сервиса контролировать, чтобы у одного пользователя была только одна запись в `news_poll_votes`.
2. **Интеграция с системой аудита**:
   - Использовать существующую в проекте инфраструктуру аудита (`emit_news_audit`) для логирования всех ключевых действий с опросами (создание, закрытие, переоткрытие, удаление).
3. **Денормализация**:
   - Внедрить денормализованное поле `votes_count` в таблицу `news_poll_options` для повышения производительности при получении результатов голосования и рендеринге новости.
4. **Фронтенд-интеграция**:
   - Разместить компонент просмотра опроса `<NewsPoll />` в `./frontend/src/pages/NewsDetailPage.vue`, а форму редактирования и создания опроса интегрировать в `./frontend/src/pages/NewsFormPage.vue`.
