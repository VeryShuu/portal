# Документация: Модуль опросов для новостей (News Polls)

> **Когда читать:** опросы как компонент новости (0..1 на новость).
> **Ключевой код:** `app/api/news/`, `app/models/news.py`, `frontend/src/components/news/poll/`, `frontend/src/components/news/poll-panel/`.
> **ADR:** —.

Этот документ описывает техническую реализацию, структуру базы данных, спецификацию REST API, логику прав доступа и устройство фронтенд-компонентов для опросов, привязанных к новостям.

---

## 1. Контекст и подход

Опрос — это **компонент новости** (по аналогии с галереей изображений и вложениями). Он не является самостоятельной сущностью в ленте. Одна новость может содержать **0..1 опрос**.

### Ключевые принципы:
- **Контейнер контента**: Новость выступает основным контейнером (текст + обложка + галерея + вложения + **опрос**).
- **Жизненный цикл**: Жизненный цикл опроса жёстко связан с новостью. При удалении новости опрос и все связанные данные удаляются каскадно (`ON DELETE CASCADE`). Однако опрос имеет собственный статус (`open` / `closed`) и собственное время окончания `closes_at`.
- **Голосование**: Отдельная подсистема с собственными правами доступа, ограничениями и API-эндпоинтами.

## 2. Модель данных и БД

Архитектура хранения спроектирована с использованием двух основных таблиц опросов/вариантов и двух вспомогательных таблиц для обеспечения транзакционности и контроля уникальности голосования при `is_multiple = false` / `true`.

### 2.1. Таблица `news_polls` (Опросы)
Хранит общую конфигурацию и метаданные опроса. Связана с таблицей новостей один-к-одному.

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | Уникальный идентификатор опроса (server-default `gen_random_uuid()`) |
| `news_id` | UUID FK | Ссылка на `./backend/app/models/news.py` `news.id` (`ON DELETE CASCADE`, `UNIQUE`) |
| `is_anonymous` | BOOLEAN | Анонимный ли опрос (результаты выводятся агрегированно, по умолчанию `true`) |
| `allow_revote` | BOOLEAN | Разрешено ли менять свой голос (по умолчанию `false`) |
| `results_visibility` | VARCHAR(20) | Режим видимости результатов (`always`, `after_vote`, `after_close`, `only_admin_editor`); default `after_vote` |
| `closes_at` | TIMESTAMPTZ | Плановая дата и время закрытия (nullable) |
| `closed_at` | TIMESTAMPTZ | Фактическая дата и время закрытия опроса (nullable) |
| `created_at` | TIMESTAMPTZ | Время создания (default `NOW()`) |
| `updated_at` | TIMESTAMPTZ | Время последнего изменения (default `NOW()`) |

#### Ограничения:
- `ck_news_polls_results_visibility`: `results_visibility IN ('always', 'after_vote', 'after_close', 'only_admin_editor')`

### 2.2. Таблица `news_poll_questions` (Вопросы опроса)
Хранит вопросы опроса. Один опрос содержит от 1 до 30 вопросов.

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | Уникальный идентификатор вопроса (server-default `gen_random_uuid()`) |
| `poll_id` | UUID FK | Ссылка на `news_polls.id` (`ON DELETE CASCADE`) |
| `text` | VARCHAR(500) | Текст вопроса (not null) |
| `sort_order` | INTEGER | Порядок отображения (по умолчанию `0`) |
| `is_required` | BOOLEAN | Является ли вопрос обязательным (по умолчанию `true`) |
| `is_multiple` | BOOLEAN | Разрешено ли выбирать несколько вариантов (по умолчанию `false`) |
| `max_choices` | INTEGER | Максимальное число вариантов при множественном выборе (nullable) |
| `allow_custom_answer` | BOOLEAN | Разрешён ли произвольный текстовый ответ (по умолчанию `false`) |
| `created_at` | TIMESTAMPTZ | Время добавления (default `NOW()`) |

#### Ограничения и индексы:
- `ck_news_poll_questions_max_choices`: `max_choices IS NULL OR (is_multiple = true AND max_choices >= 1)`
- `idx_news_poll_questions_poll_sort`: Индекс по `(poll_id, sort_order)`.

### 2.3. Таблица `news_poll_options` (Варианты ответов)
Хранит возможные варианты ответов для конкретного вопроса. Поддерживает как текстовые, так и визуальные опросы.

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | Уникальный идентификатор варианта (server-default `gen_random_uuid()`) |
| `question_id` | UUID FK | Ссылка на `news_poll_questions.id` (`ON DELETE CASCADE`) |
| `text` | VARCHAR(200) | Текст варианта (nullable, если заполнена картинка) |
| `image_url` | VARCHAR(500) | URL изображения для визуальных опросов (nullable) |
| `sort_order` | INTEGER | Порядок отображения (по умолчанию `0`) |
| `votes_count` | INTEGER | Денормализованное поле для быстрого подсчёта голосов (default `0`). Пересчитывается в той же транзакции через сервисный слой из таблицы `news_poll_votes` под advisory-блокировкой пользователя. Триггеры БД не используются. |
| `created_at` | TIMESTAMPTZ | Время добавления (default `NOW()`) |

#### Ограничения и индексы:
- `ck_news_poll_options_text_or_image`: `text IS NOT NULL OR image_url IS NOT NULL` (каждый вариант должен иметь текст или изображение)
- `idx_news_poll_options_question_sort`: Индекс по `(question_id, sort_order)` для быстрой выборки отсортированных вариантов.

### 2.5. Таблица `news_poll_voters` (Проголосовавшие пользователи)
Хранит факт участия пользователя в опросе для предотвращения накруток и поддержки изменения голоса.

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | Уникальный идентификатор факта голосования (server-default `gen_random_uuid()`) |
| `poll_id` | UUID FK | Ссылка на `news_polls.id` (`ON DELETE CASCADE`) |
| `user_id` | UUID FK | Ссылка на `users.id` (`ON DELETE CASCADE`) |
| `created_at` | TIMESTAMPTZ | Дата и время голосования (default `NOW()`) |

#### Ограничения и индексы:
- `uq_news_poll_voters_poll_user`: Уникальный ключ по `(poll_id, user_id)` гарантирует, что пользователь регистрируется в опросе ровно один раз.
- `idx_news_poll_voters_user_id`: Индекс по `user_id` для быстрого получения списка опросов, в которых участвовал пользователь.

### 2.6. Таблица `news_poll_votes` (Голоса пользователей)
Связывает проголосовавшего пользователя с выбранным вариантом ответа или произвольным текстом для конкретного вопроса.

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID PK | Идентификатор записи |
| `poll_id` | UUID FK | Ссылка на `news_polls.id` (`ON DELETE CASCADE`) |
| `voter_id` | UUID FK | Ссылка на `news_poll_voters.id` (`ON DELETE CASCADE`) |
| `question_id` | UUID FK | Ссылка на `news_poll_questions.id` (`ON DELETE CASCADE`) |
| `option_id` | UUID FK | Ссылка на `news_poll_options.id` (`ON DELETE CASCADE`); nullable (NULL при произвольном ответе) |
| `custom_text` | VARCHAR(500) | Произвольный текстовый ответ (nullable; используется при `allow_custom_answer = true`) |
| `created_at` | TIMESTAMPTZ | Время записи голоса (default `NOW()`) |

#### Ограничения и индексы:
- `ck_news_poll_votes_kind`: `(option_id IS NOT NULL AND custom_text IS NULL) OR (option_id IS NULL AND custom_text IS NOT NULL)` — каждая запись содержит либо выбор варианта, либо произвольный текст.
- `idx_news_poll_votes_question_option`: Индекс по `(question_id, option_id)` для быстрого подсчёта агрегатов.
- `idx_news_poll_votes_voter_question`: Индекс по `(voter_id, question_id)` для поиска ответов пользователя.

> **Замечание.** Уникальность «один голос на пользователя» при `is_multiple = false` гарантируется на уровне приложения (валидация в сервисном слое, advisory-блокировка по `(poll_id, user_id)` и проверка наличия записи в `news_poll_voters`). При `is_multiple = true` пользователь правомерно создаёт несколько записей `news_poll_votes` для одного вопроса.

## 3. Матрица прав доступа (Roles Matrix)

Права доступа разделены по ролям пользователей в системе (аноним, авторизованный пользователь, редактор, администратор). Управление опросом (создание, изменение, удаление, принудительное закрытие/переоткрытие) доступно **только редакторам и администраторам**. Голосовать может **любой авторизованный пользователь**.

| Действие | Аноним | Пользователь | Редактор | Админ |
|---|---|---|---|---|
| **Видеть опрос** | ✓ (если новость доступна) | ✓ | ✓ | ✓ |
| **Голосовать** | ✗ | ✓ | ✓ | ✓ |
| **Видеть результаты** | По правилам `results_visibility` | По правилам `results_visibility` (в т.ч. `only_admin_editor` → ✗) | ✓ всегда | ✓ всегда |
| **Создать / Изменить / Удалить опрос** | ✗ | ✗ | ✓ | ✓ |
| **Принудительно закрыть / переоткрыть** | ✗ | ✗ | ✓ | ✓ |
| **Видеть список проголосовавших** | ✗ | Только если `is_anonymous = false` | ✓ всегда (в т.ч. при `is_anonymous = true`) | ✓ всегда (в т.ч. при `is_anonymous = true`) |

## 4. Спецификация Backend API

Управление и голосование реализуются по базовому префиксу: `/api/news/{news_id}/poll`

### 4.1. Чтение (доступно всем согласно матрице прав)

- **`GET` `/api/news/{news_id}/poll`**
  - **Описание**: Получение полной информации об опросе, включая денормализованные счётчики, расчёт процентов голосов и метаданные о голосе текущего пользователя. Видимость результатов фильтруется на сервере согласно `results_visibility` и роли вызывающего.
  - **Ответ**: Схема `NewsPollResponse`.

### 4.2. Эндпоинты управления (Редакторы / Админы)

- **`POST` `/api/news/{news_id}/poll`**
  - **Описание**: Создание опроса для новости. Доступно только редакторам и администраторам.
  - **Тело запроса**: `CreateNewsPollRequest` (список `questions` (1–30 шт.), для каждого — `text`, `is_required`, `is_multiple`, `max_choices`, `allow_custom_answer` и список `options`; глобально — `is_anonymous`, `allow_revote`, `results_visibility`, `closes_at`).

- **`PATCH` `/api/news/{news_id}/poll`**
  - **Описание**: Частичное обновление настроек опроса. Доступно только редакторам и администраторам.
  - **Тело запроса**: `UpdateNewsPollRequest`.
  - **Ограничение (замок голосов)**: Если в опросе уже есть хотя бы один голос, эндпоинт запрещает изменять структуру вопросов и вариантов (добавление, удаление, изменение `sort_order`). Разрешается только обновлять `closes_at`, тексты существующих вопросов и вариантов.

- **`DELETE` `/api/news/{news_id}/poll`**
  - **Описание**: Удаление опроса. Каскадно очищает вопросы, варианты, голоса и записи `news_poll_voters`. Доступно только редакторам и администраторам.

- **`POST` `/api/news/{news_id}/poll/close`**
  - **Описание**: Ручное принудительное закрытие опроса (выставляет `closed_at = NOW()`). Доступно только редакторам и администраторам.

- **`POST` `/api/news/{news_id}/poll/reopen`**
  - **Описание**: Переоткрытие закрытого опроса (сбрасывает `closed_at` в `NULL`). Разрешено, если `closes_at IS NULL` либо `closes_at > NOW()`. Доступно только редакторам и администраторам.

### 4.3. Эндпоинты голосования (Любой авторизованный пользователь)

- **`POST` `/api/news/{news_id}/poll/vote`**
  - **Описание**: Голосование — передача ответов на один или несколько вопросов. Доступно любому авторизованному пользователю.
  - **Тело запроса**: `{ "answers": [{ "question_id": "uuid", "option_ids": ["uuid-1", ...], "custom_text": "..." }] }`. Каждый элемент `answers` соответствует одному вопросу; `option_ids` и `custom_text` взаимоисключающи в рамках одной записи голоса.
  - **Бизнес-логика**:
    1. Проверка существования опроса и принадлежности вопросов/вариантов данному опросу.
    2. Проверка, закрыт ли опрос (если `closed_at` выставлен или `closes_at <= NOW()`, выдаётся `409 Conflict`).
    3. Для каждого вопроса: при `is_multiple = false` ответ должен содержать ровно 1 элемент (вариант или `custom_text`). При `is_multiple = true` суммарное количество выборов должно укладываться в `max_choices` (если задано). Обязательные (`is_required = true`) вопросы должны иметь непустой ответ.
    4. Если пользователь уже голосовал, а `allow_revote = false`, возвращается ошибка `409 Conflict`. Если `allow_revote = true`, прежние записи `news_poll_votes` пользователя удаляются, запись в `news_poll_voters` остаётся (фиксируется факт участия), денормализованные счётчики `votes_count` пересчитываются, после чего записываются новые голоса.
    5. Выполняется под PostgreSQL advisory-блокировкой (`pg_advisory_xact_lock`) с ключом, вычисляемым как `hashtextextended(poll_id::text || ':' || user_id::text, 0)` — этим обеспечивается сериализация конкурентных голосований одного пользователя в одном опросе и предотвращается race condition.

- **`DELETE` `/api/news/{news_id}/poll/vote`**
  - **Описание**: Отзыв своего голоса (разрешён только при `allow_revote = true` до закрытия опроса). Доступно любому авторизованному пользователю — относительно собственного голоса.

## 5. Валидация и бизнес-правила

1. **Создание опроса**: Опрос должен содержать от 1 до 30 вопросов (`CreateNewsPollRequest`). Каждый вопрос должен иметь от 2 до 20 вариантов ответов. Тексты вариантов одного вопроса не должны дублироваться.
2. **Контроль вариантов**: Каждый вариант должен содержать либо `text`, либо `image_url` (или оба). Варианты без текста и картинок запрещены.
3. **Замок на структуру**: При наличии голосов структура вопросов и вариантов "замораживается". Нельзя добавлять новые варианты, удалять существующие или менять порядок `sort_order`.
4. **Видимость результатов**:
   - `always`: результаты видны всем и всегда.
   - `after_vote`: результаты скрыты для пользователя, пока он не проголосует (или пока опрос не закроется).
   - `after_close`: результаты скрыты для всех обычных пользователей, пока опрос не закроется (не наступит `closes_at` или `closed_at`).
   - `only_admin_editor`: результаты скрыты для обычных пользователей в любой момент времени (даже после окончания опроса). Видны только редакторам и администраторам.
5. **Анонимность**: При установленном флаге `is_anonymous = true` система скрывает связь `user_id` с конкретными `option_id` во всех публичных эндпоинтах. Счётчики выдаются только в агрегированном виде.

```python
# Логика фонового автозакрытия в ./backend/app/worker/tasks/news.py
# Находит все опросы, у которых closes_at <= NOW() и closed_at IS NULL,
# проставляет им closed_at = NOW() и логирует событие закрытия в аудит.
```

## 7. Фронтенд-компоненты

Реализация пользовательского интерфейса выполнена с использованием Vue 3, Naive UI, TanStack Vue Query и Vue I18n.

### 7.1. Компонент голосования `<NewsPoll />`
Файл реализации: `./frontend/src/components/news/poll/NewsPoll.vue`.
Интегрирован в нижнюю часть детального просмотра новости в `./frontend/src/pages/NewsDetailPage.vue`.

- **Состояния отображения**:
  - *Загрузка*: Отображает аккуратный skeleton-загрузчик.
  - *Опрос открыт и не проголосован*: Рендерит список вариантов в виде радиокнопок (при `single-choice`) или чекбоксов (при `multiple-choice`). Если у вариантов есть изображения, они отображаются в виде плитки с крупными тач-зонами. Кнопка «Проголосовать» активна при наличии выбора.
  - *Опрос открыт и проголосован*: Отображает результаты опроса в виде анимированных прогресс-баров с указанием процентов голосов, подсвечивает выбранные пользователем варианты и предоставляет кнопку «Изменить голос» (если `allow_revote = true`).
  - *Опрос закрыт*: Отображает финальные результаты, помечает выбранные варианты, скрывает интерактивные элементы ввода и выводит бейдж «Опрос завершён».
  - *Скрытые результаты*: Выводит варианты без процентов и счётчиков с текстом «Результаты будут видны после...» в зависимости от настроек видимости.
  - *Для неавторизованных*: Выводит варианты ответов в неактивном режиме и отображает призыв войти (CTA-кнопка), перенаправляющую на страницу авторизации с сохранением обратного URL (`redirect`).

- **Доступность (a11y)**:
  - Используются семантические теги `<fieldset>` и `<legend>` для названия вопроса.
  - Атрибуты `role="progressbar"`, `aria-valuenow` и `aria-valuemax` для прогресс-баров результатов.
  - Полноценная поддержка навигации с клавиатуры.

### 7.2. Панель редактора опроса `<NewsPollPanel />`
Файл реализации: `./frontend/src/components/news/poll-panel/NewsPollPanel.vue`.
Интегрирован в форму создания и редактирования новости в `./frontend/src/pages/NewsFormPage.vue`. Панель рендерится только пользователям с ролью редактора или администратора; остальным ролям компонент не отображается.

- **Возможности управления**:
  - Добавление опроса к новости (доступно только после сохранения черновика новости, когда сгенерирован её `news_id`, и только для редакторов/администраторов).
  - Ввод вопросов (до 30 штук), гибкое управление вариантами в каждом вопросе (добавление до 20 штук, быстрое удаление, изменение порядка кнопками вверх/вниз).
  - Настройка параметров: анонимность, переголосование, выбор даты автозакрытия `closes_at` и режима видимости результатов. На уровне каждого вопроса — множественный выбор, лимит `max_choices`, обязательность и поддержка произвольного ответа.
  - Интеграция с замком голосов: если в опросе уже есть голоса (`total_voters > 0`), редактор блокирует поля добавления, удаления и изменения порядка вопросов/вариантов, позволяя лишь продлевать/сокращать дату окончания или корректировать опечатки в текстах.

### 7.3. Компонент карточки новости `<NewsCard />`
При наличии активного опроса в новости на карточке в ленте (`./frontend/src/components/NewsCard.vue`) выводится компактный индикатор-иконка «Опрос», информирующий пользователей о возможности проголосовать.
