## 1. Цель и контекст

Модуль обучения сотрудников на портале (функциональный аналог Moodle в ограниченном
объёме). Ключевое отличие от остальных модулей портала — **публичный контур**:
обучение доступно не только из интранета/VPN, но и из интернета, при этом портал
в целом остаётся закрытым.

Две категории обучаемых:
- **Сотрудники портала** (основная масса) — ходят на курсы через портал как обычно,
  свой SSO-вход, ничего нового не замечают, кроме раздела «Обучение».
- **Внешние учётки** — люди без учётной записи Keycloak (создаются админом модуля:
  ФИО + email + пароль). Заходят через отдельный публичный домен `learn.<домен>`.

Исходное обсуждение (сетевая схема, альтернатива «отдельный realm Keycloak»,
критика сессионной модели) — см. журнал решений §12. Под сетевые/доменные изменения
пишется отдельный ADR (ADR-050, зарезервировано).

Подход к поставке: слово «MVP» не используем — это **продовый модуль с первого
выпуска**; объём растёт этапами (этап 1 описан в §6–§10, дальнейшие — §15), каждый
этап проходит полный цикл качества (тесты/линт/доки) и выезжает на прод без
временных заглушек. Терминов вида «черновой контур» в проекте нет.

### Принцип: это модуль портала, не отдельный продукт

Максимально задействуем готовую инфраструктуру, оформление и паттерны портала —
никакой «второй системы» внутри репозитория:

- Бэкенд — тот же процесс: `app/api/learning/`, сервисы и модели по общим
  конвенциям; нового контейнера/процесса нет, деплой прежний.
- Инфраструктура — новое только то, чего физически нет: server-блок nginx по
  готовым шаблонам `nginx/templates/` + DNS/TLS на learn-домен (§11).
  Postgres/Redis/SMTP/мониторинг — существующие.
- Аутентификация: сотрудники — текущие портальные сессии; learner — та же схема
  «Redis + HTTPOnly cookie», своё пространство ключей.
- Оформление: Naive UI + design-tokens портала, общий брендинг (лого/фавикон);
  раздел «Обучение» обязан выглядеть частью портала, а не сторонним софтом.
- Админ-UX: мастер-переключатель в ModulesTab (`modules.json` → ключ `learning`),
  контекстные настройки через manage-drawer (`?manage=`) — как у остальных модулей.
- Почта/файлы/журналы: outbox-паттерн; `/data/learning/` — третий легитимный
  локальный корень по прецедентам photos/helpdesk; structlog c redact-процессорами;
  `push_audit_event(...)` для admin-мутаций.
- Фронтенд: learn-точка входа — отдельный html-entry того же SPA-проекта (общая
  кодовая база и дизайн-система); stores/queries/i18n — строго по конвенциям.
- Качество: все обязательные CI-гейты распространяются на learning-код наравне
  с остальным (drift-checks, diff-coverage ≥80%).

## 2. Термины

| Термин | Значение |
|---|---|
| Внутренний контур | `portal.mage.ru` — как сегодня, CIDR/VPN |
| Публичный контур | `learn.mage.ru` — новый server-блок nginx, только учебные пути |
| Внешняя учётка (learner) | Запись в `learning_accounts`, живёт вне `users` и вне Keycloak |
| Участник курса | Сотрудник портала ИЛИ внешняя учётка, записанные на курс |
| Методист | Единственная штатная роль модуля (= админ модуля, таблица `learning_admins`); права на все курсы |

## 3. Роли (внутри модуля, не трогают глобальные роли `users.role`)

Одна штатная роль модуля — **методист** (= админ модуля): как агенты техподдержки,
назначаются в отдельную таблицу `learning_admins` (паттерн `helpdesk_agents`),
зависимость `require_learning_admin` (по образцу `require_helpdesk_agent`).

| Роль | Кто | Может |
|---|---|---|
| `training_admin` (методист) | сотрудник портала, назначается глобальным админом в `learning_admins` | всё внутри модуля: курсы/материалы/тесты (**все** курсы, без деления на «свою зону»), внешние учётки (создание, импорт, блокировка, сброс пароля), зачисление/исключение участников, прогресс/отчёты |
| `learner` | сотрудник портала или внешняя учётка | прохождение назначенных курсов |

Права модуля хранятся отдельно от глобальной матрицы (`docs/roles-matrix.md`
дополняется разделом). Глобальная роль `admin` портала — суперсет `training_admin`.

## 4. Архитектура доступа

```
интернет ──> WAF ──> learn.mage.ru (nginx, публичный server-блок)
                      ├── статика фронтенда (только учебные страницы)
                      ├── /api/v1/learning/me/*   → backend
                      ├── /api/v1/learning/meta   → backend
                      └── /api/v1/auth/learning/* → backend
                      (остальной /api/v1/learning/* — admin/methodist — и всё
                       прочее: 404 на уровне nginx, PA-003)

интранет/VPN ──> portal.mage.ru (без изменений)
                      └── /learning — те же курсы для сотрудников
```

- `portal.mage.ru` не меняется: CIDR-фильтрация как сегодня (`nginx/templates/*.tmpl`,
  `if ($allowed_network = 0) { return 403; }`).
- Публичный server-блок **не** содержит CIDR-проверки и **не** проксирует ничего,
  кроме перечисленного. Список путей — явный allowlist в шаблоне.
- **Keycloak на публичном контуре отсутствует**: SSO там нет вообще, поэтому проблемы
  callback-URL (`_helpers.py:40`), второго CORS-origin и SSO-ветвления фронтенда
  не возникают.
- CSRF middleware (`app/middleware/csrf.py`): Origin-allowlist из двух базовых URL —
  `portal_base_url` + `learning_base_url` (новое поле в `system.json`, валидируется
  со scheme, как `portal_base_url`). Оба контура same-origin (фронт и API на одном
  хосте), CORS не расширяется. Auth-пути (логин/forgot/reset) добавляются в Origin-only
  список `_CSRF_ORIGIN_ONLY_PATHS` — на логине cookie ещё нет, double-submit невозможен
  (паттерн local-login).
- WAF: доверие через `set_real_ip_from` + `real_ip_header` (nginx). Сейчас портал
  намеренно не доверяет forwarded-заголовкам (`system_data/nginx/nginx.conf:104`) —
  без realip rate-limiter увидит IP WAF, и все внешние обучаемые упрутся в один
  общий лимит. Реализация — на стороне инфраструктуры (Reydan), в ТЗ фиксируется
  требование.

## 5. Внешние учётки

### 5.1 Создание — только админом модуля

Открытой саморегистрации нет. Два способа: поштучно и импортом.

**Импорт из Excel** (xlsx):
- Шаблон скачивается из админ-UI (правило «каждый импорт — со скачиваемым
  шаблоном» теперь общее для модуля, §13). Колонки: `Фамилия Имя` (или `Имя Фамилия` — одна
  колонка full_name), `email` — обязательны; `отдел`, `должность` — опциональны
  (хранятся как справочные данные учётки, нигде не смешиваются со штатным
  справочником `users`).
- Разбор на бэкенде (`openpyxl`, read-only; зависимость уже в `pyproject.toml`
  — используется ERP-синком; ревью 2026-08-28: отдельное согласование не нужно).
  Ячейки читаются принудительно как строки (Excel любит превращать телефоны
  и табельные номера в числа/даты).
- Поведение при дублях (email уже существует в `learning_accounts`): строка
  пропускается, не ошибкой; по итогу импорта возвращается отчёт
  «создано N / пропущено M (дубли) / ошибок K (невалидные строки)».
- Импорт транзакционен по валидным строкам; строки с ошибками не блокируют остальные.
- Лимит: до ~1000 строк за импорт.

### 5.2 Пароли

- При создании учётки (поштучно или импортом) пароль **генерируется автоматически**
  (крипто-случайный, `secrets`, ≥12 символов) и отправляется на email учётки.
  Пароль **временный**: `must_change_password = true`, принудительная смена при
  первом входе (без смены — дальше входа не пустить).
- **Сброс пароля админом**: `training_admin` в админ-UI нажимает «Сбросить пароль» →
  генерируется новый временный пароль → письмо на email учётки → инвалидация всех
  её сессий (`learning_sessions:*` index) → `must_change_password = true`.
- **Самовосстановление** («Забыли пароль?» на learn-домене): email → одноразовый
  токен (в БД только хэш токена, TTL 60 мин) → письмо со ссылкой → смена пароля →
  инвалидация всех сессий. Ответ эндпоинта одинаковый независимо от существования
  email (anti-enumeration, паттерн `DUMMY_HASH` из `app/core/security.py`).
- Хэширование — существующее `hash_password`/`verify_password` (bcrypt, cost 12).
- Учётки: progressive delay с первых неудачных входов (настройка); порог N неудач
  подряд (настройка, default 5) → блок учётки на T минут (default 15) →
  само-разблокировка; счётчик и задержка сбрасываются успешным входом.
  Решение (Reydan, 2026-08-26): cooldown авто — внешний обучаемый не упирается
  в поддержку при опечатках/переборе. Постоянная блокировка (`status=blocked`)
  — отдельное ручное действие методиста, с автоматической не связана.
- Секреты живут только в письме: временный пароль и токены восстановления
  запрещено класть в payload аудита, логи и ответы API (redact-процессоры про эти
  поля не знают и сами их не замаскируют).

### 5.3 Уведомления (всё через `enqueue_outbox_email`, kind=`learning`)

Обязательные рассылки:
1. **Создание учётки** — email: «для вас создана учётка обучения» + временный
   пароль + ссылка `learn.<домен>`.
2. **Зачисление на курс** — email: «вы зачислены на курс <название>» + прямая
   ссылка на курс. Получатели: и внешние учётки, и сотрудники портала (на их
   корпоративный email).
3. **Сброс пароля** — письмо с новым временным паролем (для админ-сброса).
4. **Восстановление пароля** — письмо со ссылкой-токеном.

Транзакционность — по outbox-паттерну: письмо ставится в той же транзакции, что и
бизнес-операция. SMTP обязан доставлять на внешние адреса; до запуска — проверить
SPF/DKIM домена (инфра-задача, зафиксирована в DoD).

## 6. Курсы

### 6.1 Структура
- Курс: название, описание (rich-text — Markdown, редактируется методистом тем же
  TipTap-редактором, что новости/БЗ; sanitize на записи, рендер под DOMPurify —
  ревизия 2026-08-31), обложка (опционально; **этап 2** — поле БД есть,
  API/UI отдельным инкрементом, решение Reydan 2026-08-28), статус
  черновик/опубликован, список участников, упорядоченный список элементов.
- Publish-gate (ревью 2026-08-28 + 2026-08-30): опубликовать курс можно, только
  если каждый активный материал имеет ссылку или PDF-файл И каждый тест имеет
  хотя бы один вопрос с вариантами — иначе 422. Инвариант сохраняется после
  публикации: добавить пустую заготовку PDF или пустой тест в опубликованный
  курс нельзя (409 — сначала снять курс с публикации); добавление и публикация
  сериализуются одним row-lock курса.
- Удаление: курс — soft всегда (попытки/прогресс остаются в истории §7,
  недоступный курс закрывает и доступ к попыткам); **тест с попытками
  удалить нельзя** — только копией (§15).
- Элементы курса двух типов (первая поставка):
  - **Материал**: PDF-файл или внешняя ссылка (URL); видео-ссылки из
    доверенного списка встраиваются плеером (§6.2).
  - **Тест**: см. 6.3.
- Уникальная ссылка курса: `learn.<домен>/courses/<slug>` и
  `portal.mage.ru/learning/courses/<slug>` — один курс, оба домена.
  Знание ссылки доступ не даёт: попадаешь на курс только если ты в списке
  участников (или методист/админ модуля).

### 6.2 Материалы
- PDF: загрузка методистом, download через стриминг (как вложения helpdesk —
  `StreamingResponse`, не буферизация в bytes). Хранение: **локально
  `/data/learning/materials/<course_id>/<item_id>.pdf`** по образцу исключений
  photos/helpdesk (пользовательские файлы — в Nextcloud, но учебные материалы —
  контент модуля, не личные файлы; вынесение в NC — отдельное решение, если
  понадобится). Лимит размера/тип проверяются как у загрузок портала (python-magic).
- Обложка курса (опционально, **этап 2**) — тоже локально в `/data/learning/`;
  превью генерируется Pillow (по образцу фото/news-covers).
- Ссылка: URL с валидацией схемы (http/https), открывается в новой вкладке,
  раздача через `rel="noopener"`.
- **Видео-ссылки (2026-08-31; изначально 2026-08-29 клик-плей)**: URL
  распознаётся как видео → в карточке материала рендерится встроенный плеер
  **сразу** (как в новостях/БЗ: превью с кнопкой play рисует сам плеер хостинга,
  `loading="lazy"` откладывает загрузку невидимых кадров; решение Reydan —
  «хочу как в новостях», клик-заглушка убрана); исходная ссылка остаётся рядом
  («открыть в новой вкладке»). Список разрешённых origin'ов — runtime-настройка
  `system.json → video_iframe_origins` (Admin UI → System; дефолт: корпоративный
  `video.mage.ru` + `YouTube` (youtube-nocookie), `RuTube`, `VK`, `Vimeo`).
  Не-видео или неразрешённые ссылки ведут себя как раньше. Список един для
  CSP обоих контуров, sanitize-гейта новостей/БЗ и гейта плеера; известные
  провайдеры (конвертация ссылок в embed-URL) — код (`utils/videoEmbed.ts`),
  не настройка. Learn-сборка получает список через `GET /learning/meta`
  (bootstrap на ней нет). media-src не открывается — плеер живёт внутри
  iframe хостинга.

### 6.3 Тесты
- Вопросы с вариантами ответа: один правильный / несколько правильных
  (single/multi choice); свободный текст и соответствие — этап 2+ по потребности;
  SCORM и прочие форматы-контейнеры не планируются вовсе (§15).
- Параметры теста: проходной балл (%), лимит попыток (0 = неограниченно),
  перемешивание вариантов и вопросов (да/нет).
- Баллы: вопросы равновесные (итог = доля верных вопросов); вопрос с несколькими
  правильными засчитывается только при полном совпадении набора — частично верный = 0.
- Попытка: студент отвечает на все вопросы → submit → результат (балл, passed).
  Промежуточного сохранения черновика попытки нет. Лимит проверяется при старте
  новой попытки и считается по **отправленным** попыткам: начатая и брошенная лимит
  не расходует (строка без submit помечается abandoned через 24 часа, а при
  таймере теста — сразу по истечении started_at + лимит; ревью 2026-08-30:
  иначе просроченная попытка блокировала бы участника до 24-часового cutoff).
- Правильные ответы студенту не показываются (только итоговый балл и статус).
- Пересдача — в рамках лимита попыток; зачёт курса — по последнему отправленному
  результату.
- Прогресс курса: элемент «пройден» — материал: отметка «ознакомлен» (кнопка);
  тест — passed.

## 7. Модель данных (новые таблицы; следующий свободный номер миграции — 101)

| Таблица | Ключевое |
|---|---|
| `learning_accounts` | id, full_name, email (уникальный lower), password_hash, department?, position?, status (active/blocked), must_change_password, failed_attempts, last_login_at, created_at/updated_at/deleted_at (soft) |
| `learning_password_resets` | account_id, token_hash, expires_at, used_at |
| `learning_admins` | user_id (сотрудник, unique) — членство методиста, отдельной колонки role нет (роль одна); паттерн `helpdesk_agents` |
| `learning_courses` | id, slug (уникальный), title, description, status, created_by, timestamps |
| `learning_course_items` | course_id, sort_order, type ∈ (material, test), material-поля: file_path / url; timestamps |
| `learning_course_participants` | course_id, participant: `user_id` **или** `learning_account_id` (CHECK ровно один заполнен), enrolled_by, enrolled_at, deleted_at — исключение участника только soft, попытки и прогресс остаются в истории. Уникальность — два частичных индекса: `(course_id, user_id)` WHERE `user_id IS NOT NULL AND deleted_at IS NULL` и `(course_id, learning_account_id)` WHERE аналогично. Плюс снапшот личности `display_name`/`email` на момент зачисления (миграция 103: прогресс и письма не читают `users` под ролью learning_app) |
| `learning_tests` | item_id FK, pass_score, max_attempts, shuffle |
| `learning_questions` | test_id, text, multi (bool), sort_order |
| `learning_question_options` | question_id, text, is_correct, sort_order |
| `learning_test_attempts` | participant-поля (user_id/learning_account_id), test_id, started_at, submitted_at (nullable → не засчитана), abandoned_at, score, passed, answers JSONB |
| `learning_item_progress` | item_id, participant user_id XOR learning_account_id (CHECK ровно один), completed_at — отметка «ознакомлен» материала; уникальность участник×элемент частичными индексами. % прохождения курса считается из этой таблицы + passed-попытки |

Индексы: participants по обоим FK, email_ci на accounts (аналог `idx_users_email_ci_active`),
attempts по (test, participant). Soft-delete + `ON DELETE SET NULL` для FK на users —
по конвенциям БД проекта.

Сессии внешних учёток — **Redis, не таблица**: `learning_session:{id}` (HTTPOnly
cookie `learning_session`, host-only для learn-домена, TTL 8ч, sliding window),
индекс `learning_sessions:{account_id}` для «выйти со всех устройств». Payload:
`{"principal_type": "learning_account", "account_id": ...}`. Пространство ключей
отдельно от `session:*` — смешение невозможно; `get_current_user` портала эти
сессии не читает (принципалы типизированы: `CurrentPortalUser` / `CurrentLearner` /
`CurrentLearningParticipant` — последний допускает обоих, только для learning-роутов).

## 8. API (обзор; полные контракты — по мере реализации в `docs/api-contracts.md`)

Публичный контур (`learn.<домен>`, все — rate-limited жёстче базового):
- `POST /api/v1/auth/learning/login` — email+пароль; при `must_change_password`
  выдаётся **ограниченная** сессия (флаг в payload: разрешён только
  change-password, остальные learner-эндпоинты → 403); лимиты IP 5/15мин +
  email 10/15мин (как local-login).
- `POST /api/v1/auth/learning/change-password`, `POST .../forgot`, `POST .../reset`,
  `POST .../logout`.
- `GET /api/v1/learning/me/courses`, `GET .../courses/{slug}`, `POST .../items/{id}/complete`,
  `POST .../tests/{id}/attempts`, `GET .../attempts/{id}`, `GET .../tests/{id}/my-attempts`
  (свои результаты + остаток попыток перед пересдачей).

Внутренний контур (портал, CurrentPortalUser):
- Админ-UI модуля (все эндпоинты за `require_learning_admin`): CRUD
  курсов/элементов/тестов, `POST /learning/accounts/import` (multipart xlsx),
  `POST /learning/accounts` (поштучно), `POST /learning/accounts/{id}/reset-password`,
  `POST /learning/accounts/{id}/block` и `/unblock`, `POST /learning/courses/{id}/participants`
  (user или account), исключение участника (soft).
- `GET /learning/courses/{id}/progress` — прогресс участников (обе категории в одном
  списке, с бейджем сотрудник/внешний).
- Виджет «Мои курсы» для сотрудников — те же данные, что на learn-домене.

Регистрация роутеров: `app/api/learning/` (подпакет), гейт модулем
`modules.json` → ключ `learning` (мастер-переключатель, паттерн `require_helpdesk_module`).

## 10. Безопасность (сводка обязательных мер)

1. Nginx-allowlist публичного контура + отсутствие Keycloak на нём.
2. Типизированные принципалы; learner-сессия несовместима с deps портала —
   фиксируется явным unit-тестом (401 на штатный эндпоинт с learner-cookie).
3. Rate limits: вход/восстановление — IP+email (fastapi-limiter) + nginx-зона
   для `/api/v1/auth/learning/`; прогрессивная задержка + cooldown-блок учётки (§5.2).
4. Anti-enumeration: одинаковые ответы forgot-password; DUMMY_HASH-паттерн на логине.
5. Одноразовость и TTL токенов восстановления; хранится только хэш.
6. Инвалидация всех сессий при сбросе/смене пароля.
7. Cookie `learning_session` — host-only, HTTPOnly, Secure, SameSite=Lax.
8. Отдельная DB-роль **с первой поставки** (решение Reydan: «делать сразу нормально»): второй
   SQLAlchemy engine/пул только для learning-роутов; креды роли с грантами лишь на
   `learning_*` таблицы + точечные INSERT-only на общие служебные (`email_outbox`,
   аудит-таблица) — outbox-письмо из learning-транзакции должно работать, а вот
   SELECT чужих таблиц ролью невозможен. Integration-тест: запрос под learner-кредами
   к `users` → отказ доступа.
9. Аудит всех admin-мутаций; логирование без PII/секретов (redact-процессоры уже
   есть, но новые поля — временные пароли и токены восстановления — не должны попадать
   в аудит/логи/API-ответы по построению, см. §5.2).
10. Перед публикацией контура: security-прогон (пентест-чеклист/OWASP ZAP по
    публичным эндпоинтам), мониторинг и алерты на всплески 401/429 (Loki/Alertmanager).

### Прод-ввод модуля в эксплуатацию — пошагово

**Внутренний контур (обучение сотрудников):**

1. **Релиз**: `./scripts/release.sh v1.X.Y` (semver, чистое дерево) → CI
   публикует образы + deploy-bundle. Обучение должно попасть в релиз целиком
   (миграции 101–103 включительно).
2. **Прод-сервер**: `docker compose pull && docker compose up -d`
   (ADR-045/046; локальная сборка на проде запрещена). При старте backend
   `migrate.sh` применит миграции сам — вручную `alembic upgrade` не запускать.
3. **Проверить `LEARNING_DB_PASSWORD` в `.env`** — на проде **обязателен**
   (миграция 102 создаёт DB-роль `learning_app`, второй движок включается
   только при заданном пароле; без него learning-роуты работают на общем
   движке). `setup.sh` генерирует пароль с 2026-08-30; пароль роли
   **синхронизируется с окружением при каждом старте миграций**
   (`scripts/ensure_learning_db_role.py`), поэтому задать/сменить переменную
   можно и после первого подъёма: правка `.env` → `docker compose up -d` —
   роль обновится сама. При старте без пароля backend пишет warning
   `learning.db_role_engine_disabled` — на проде так быть не должно.
4. **Проверить применение миграций**: в логах backend нет ошибок; в БД есть
   таблицы `learning_*` и роль `learning_app` (integration-тест изоляции —
   `test_learning_db_role.py`).
5. **Включить модуль**: Admin UI → Modules → «Обучение» (`modules.json`).
   До включения все learning-роуты отдают 404.
6. **Admin UI → System, проверить поля контуров**:
   - `portal_base_url` — со схемой (`https://...`), иначе CSRF-проверка
     ломает вход (gotcha AGENTS.md);
   - `learning_base_url` — для внутреннего контура можно оставить пустым
     (публичный вход не рендерится — fail-closed, ADR-051).
7. **Admin UI → System → «Видео в iframe (CSP)»** (`video_iframe_origins`,
   ADR-052): дефолт — 6 origin'ов (video.mage.ru, youtube-nocookie, rutube,
   vk.com, vkvideo.ru, player.vimeo.com). Свой видеосервер — добавить origin
   (`https://host[:port]`); убранный хостинг перестаёт встраиваться (ссылки
   становятся внешними). После сохранения CSP обновляется sidecar'ом без
   рестарта; проверить: `curl -sI https://portal.<домен>/ | grep -i
   content-security-policy` → в `frame-src` видны выбранные origin'ы.
8. **Назначить методиста**: Admin → Обучение → «Методисты» (только глобальный
   админ портала; методист = админ модуля, §3). **Смоук на проде**: черновик
   курса → материал-ссылка (YouTube/RuTube — в карточке появится клик-плей
   плеер) + PDF → публикация → зачисление сотрудника → прохождение + тест.

**Публичный контур learn.<домен> (шаги 9–12, инфраструктура Reydan §11):**

9. **DNS + TLS**: A-запись learn.<домен> → WAF/сервер; сертификат

10. **WAF + realip**: наружу публикуется только learn-хост; nginx должен
    видеть реальный IP клиента (`set_real_ip_from` + `real_ip_header` в
    `system_data/nginx/nginx.conf`) — иначе rate-лимитеры видят один адрес

11. **Внешняя SMTP + SPF/DKIM**: письма учёток/восстановления уходят наружу —

## 15. Этапность и анализ Moodle

Moodle — эталонный открытый LMS (наш функциональный ориентир). Берём **концепции**,
не форматы и не UI; всё ниже — внедрение через паттерны портала.

| Из Moodle | Как применяем у нас | Этап |
|---|---|---|
| Неизменяемость вопросов при существующих попытках (версии) | Правило: тест, по которому есть попытки (в т.ч. начатые), правится только «копией» (duplicate → правки → замена) и **не удаляется** (замок и на delete_item); удаление всего курса — soft, разрешено всегда, попытки остаются в истории. Сериализация: правка и старт попытки держат `FOR UPDATE` одной строки `learning_tests` (ревью 2026-08-28). Попытка хранит снапшот порядка показа в `answers` JSONB | 1 |
| Перемешивание **вопросов** (а не только вариантов) | Одна булева опция теста (уже внесено в §6.3) | 1 |
| Вопросный банк (общее хранилище, реюз между тестами; в Moodle 5 вынесен из квиза) | Пока банк не нужен; когда появится 2-й курс с похожими вопросами — таблицы банка с категориями по курсу/теме | 3 |
| Массовый ввод вопросов текстом (Aiken/GIFT) | Импорт вопросов из xlsx: вопрос / варианты / флаг верного / multi — вместе с **скачиваемым шаблоном** (лист «Пример» с single- и multi-вопросом, §13) и предпросмотром перед загрузкой | 2 |
| Сертификат о прохождении | PDF: HTML-шаблон → существующий screenshot-service (`POST /pdf`) — ноль новых зависимостей; триггер — завершение курса | 2 |
| Групповое зачисление (cohorts) | Зачисление выборкой сотрудников в админке; далее — привязка к подразделениям штатного справочника | 2–3 |

| Таймер теста | Настройка «лимит времени попытки» (серверный контроль submit) | 2 |
| Report Builder / выгрузки | Экспорт прогресса курса в xlsx силами обычной генерации (openpyxl уже в зависимостях после импорта учёток); колонки = таблице прогресса, самодокументируемо | 2 |

Сознательно НЕ берём:
- **SCORM/LTI/xAPI/H5P** — форматы-контейнеры тяжёлого e-learning и чужой рантайм;
  потребность «внешний контент» закрывает материал-ссылка.
- **Форумы/чаты курса, социальное** — запрещено правилами портала («Чего НЕ делать»).
- **Бейджи/очки/геймификация** — тот же запрет; сертификата как документа достаточно.
- **Самозапись на курс по ключу (enrolment key)** — противоречит принятой модели
  «участник назначается методом», остаётся закрытой.
- **Развитый грейдбук (шкалы, веса, категории оценок)** — подменяется нашим простым
  «% верных + passed»; усложнение без запроса.
- **Компетенции (competency frameworks)** — каркас профпригодностей с нормальной
  моделью данных; интересно, но только если появится кадровый запрос.
