# Фича: доступный архив Helpdesk

## Цель

Закрытые заявки должны быть доступны заявителю и агентам за весь период, в том
числе после переноса из `helpdesk_tickets` в `helpdesk_tickets_archive`.

## Решения по ходу

- 2026-08-13: выявлен разрыв: cron переносит closed-заявки в JSONB-архив и
  удаляет live-строку, тогда как существующие страницы архива читают только
  live API с `status=closed`.
- 2026-08-13: архив — бессрочная история. Файлы и inline-медиа не очищаются
  по TTL; хранятся в защищённом `upload_data/helpdesk` и включаются в backup.

## Грабли / контекст

- Архив хранит JSONB-снимок, а файлы хранятся бессрочно. Уже удалённые прежним
  TTL файлы можно восстановить только из backup; код не может воссоздать байты.
- Контракты `/tickets/my` и `/tickets` не следует ломать: архив требует
  отдельного read-only пути либо явного расширения, согласованного с API.
- 2026-08-13: выбрано additive-расширение существующих archive-экранов:
  `status=closed` объединяет live и архив до сортировки/пагинации, detail
  делает fallback по id. Это сохраняет URL и клиентский контракт.
- Старые архивные снимки не содержат связи файла с конкретным сообщением, но
  сохранённые `attachments_meta` позволяют скачать файл из карточки; UI выводит
  их у первого сообщения. Новые снимки сохраняют точную связь.
- Гостевые email-заявки привязываются к новому аккаунту и после архивации, чтобы
  история не зависела от момента первого входа в портал.
