# Модуль «Аналитика»

> **Когда читать:** админ-аналитика, дашборд, статистика просмотров, активность отделов, популярные файлы.
> **Ключевой код:** `./backend/app/api/analytics.py`, `./frontend/src/api/analytics.ts`, `./frontend/src/pages/admin/tabs/AnalyticsTab.vue`.
> **ADR:** —

> Собственный модуль портала для администраторов (Read-Only). Позволяет в реальном времени отслеживать ключевые метрики использования интранет-портала, вовлеченность пользователей, публикационную активность, наиболее просматриваемый контент (новости, статьи Базы Знаний), популярные файлы для скачивания и уровень активности различных отделов организации. Все агрегации выполняются "на лету" (on-demand) прямыми SQL-запросами к PostgreSQL.

---

## 1. Обзор

| Аспект | Значение |
|---|---|
| **Backend** | FastAPI (`./backend/app/api/analytics.py`), SQLAlchemy, PostgreSQL (on-demand агрегация) |
| **Frontend** | Vue 3 + Naive UI (`./frontend/src/pages/admin/tabs/AnalyticsTab.vue`, `./frontend/src/api/analytics.ts`) |
| **Уровень доступа** | Исключительно администраторы (`AdminDep`) |
| **Кэширование** | На стороне клиента через TanStack Query (`staleTime: 60_000` мс), на бэкенде кэширование отсутствует |

### Возможности

- **Сводный KPI-дашборд**: оперативные метрики по пользователям (всего, активные за 30 дней, активные за 1 час, новые за 30 дней), контенту и активности.
- **Временные ряды (Sparklines)**: 14-дневная динамика входов пользователей и публикаций новостных материалов.
- **Популярные статьи KB**: рейтинг опубликованных статей Базы Знаний по количеству просмотров с привязкой к разделам.
- **Популярные новости**: рейтинг опубликованных новостей по числу просмотров.
- **Топ скачиваний**: агрегация скачиваний и экспортов файлов из логов аудита за выбранный период.
- **Активность отделов**: распределение сотрудников, их сессионной активности и общего числа совершенных действий по департаментам.

## 2. REST API

Все эндпойнты модуля требуют авторизации с правами администратора (`AdminDep`) и имеют базовый префикс `/api/v1/analytics`.

| Метод | Путь | Назначение | Права |
|---|---|---|---|
| `GET` | `/api/v1/analytics/dashboard` | Сводный дашборд: общие KPI счетчики пользователей, контента, активности за последние 24ч/30д, а также серии ежедневных логинов и публикаций за последние 14 дней. | Администратор |
| `GET` | `/api/v1/analytics/top-articles` | Рейтинг статей Базы Знаний по количеству просмотров. Поддерживает Query-параметры `days` (по умолчанию 30, `1 <= days <= 365`) и `limit` (по умолчанию 20, `1 <= limit <= 100`). | Администратор |
| `GET` | `/api/v1/analytics/top-news` | Рейтинг новостей по количеству просмотров. Поддерживает Query-параметры `days` (по умолчанию 30, `1 <= days <= 365`) и `limit` (по умолчанию 20, `1 <= limit <= 100`). | Администратор |
| `GET` | `/api/v1/analytics/top-files` | Рейтинг популярных файлов по количеству скачиваний/экспортов из логов аудита. Поддерживает Query-параметры `days` (по умолчанию 30, `1 <= days <= 365`) и `limit` (по умолчанию 20, `1 <= limit <= 100`). | Администратор |
| `GET` | `/api/v1/analytics/departments` | Статистика активности по отделам (всего пользователей, активные за период, суммарное число событий). Поддерживает Query-параметр `days` (по умолчанию 30, `1 <= days <= 365`). | Администратор |

## 3. Источники данных

Все данные рассчитываются динамически с помощью SQL-запросов (без промежуточного хранения агрегированных метрик в БД).

### 3.1. Сводный дашборд (`_SCALARS_SQL`)
- **Пользователи (`users`)**:
  - `total_users`: Общее число записей в таблице `users`.
  - `active_users_30d`: Количество пользователей с `last_login_at >= now - 30 days`.
  - `new_users_30d`: Количество пользователей с `created_at >= now - 30 days`.
  - `active_users_1h`: Количество уникальных `user_id` из `audit_log`, у которых зафиксирована активность за последний час (`created_at >= now - 1 hour`).
- **Контент (`news`, `kb_articles`)**:
  - `published_news_30d`: Количество новостей в статусе `published` с `published_at >= now - 30 days` и не находящихся в корзине (`deleted_at IS NULL`).
  - `published_articles_30d`: Количество статей базы знаний в статусе `published` с `published_at >= now - 30 days` и не находящихся в корзине (`deleted_at IS NULL`).
- **Активность (`audit_log`)**:
  - `audit_24h`: Общее количество записей в таблице `audit_log` за последние 24 часа.
  - `logins_24h`: Количество успешных авторизаций (`event_type = 'auth.login'`) за последние 24 часа.

### 3.2. Временные ряды (`_DAILY_LOGINS_SQL`, `_DAILY_PUBLICATIONS_SQL`)
- **Ежедневные входы за 14 дней**: Агрегирует события `auth.login` из таблицы `audit_log`, сгруппированные по дням: `date_trunc('day', created_at)::date`. Фильтр периода: `created_at >= now - 14 days`.
- **Ежедневные публикации за 14 дней**: Агрегирует опубликованные и не удаленные новости из таблицы `news`, сгруппированные по дням публикации: `date_trunc('day', published_at)::date`. Фильтр периода: `published_at >= now - 14 days`.

### 3.3. Популярные статьи KB (`/api/v1/analytics/top-articles`)
- Выполняет `LEFT JOIN` между таблицами `kb_articles a` and `kb_sections s` по идентификатору секции `s.id = a.section_id`.
- Фильтрует статьи: `a.deleted_at IS NULL` (не удалена), `a.status = 'published'` (опубликована), и дата публикации или обновления попадает в заданный интервал (`a.published_at >= cutoff` или `a.updated_at >= cutoff`, либо дата публикации пуста).
- Данные сортируются по `a.view_count DESC, a.updated_at DESC`.

### 3.4. Популярные новости (`/api/v1/analytics/top-news`)
- Выбирает записи из таблицы `news`, фильтруя по `deleted_at IS NULL`, `status = 'published'` и `(published_at IS NULL OR published_at >= cutoff)`.
- Сортирует по `view_count DESC, published_at DESC NULLS LAST`.

### 3.5. Топ скачиваний файлов (`/api/v1/analytics/top-files`)
- Группирует записи таблицы `audit_log` по полю `resource_id` за период `created_at >= cutoff`.
- Отслеживает только события, входящие в перечень:
  - `files.file_downloaded` — скачивание файлов из общего хранилища.
  - `photos.photo_downloaded` — скачивание оригиналов фотографий.
  - `kb.article_exported_pdf` — экспорт статей Базы Знаний в PDF.
  - `kb.article_exported_docx` — экспорт статей Базы Знаний в DOCX.
  - `news.exported` — экспорт новостей.
- Вычисляет `MAX(resource_title) AS title` для отображения имени файла, суммирует количество скачиваний `count(*) AS downloads` и определяет дату последнего скачивания `MAX(created_at) AS last_download`. Сортировка выполняется по `downloads DESC`.

### 3.6. Активность по отделам (`/api/v1/analytics/departments`)
- Формирует список уникальных департаментов на основе поля `department` из таблицы `users u` (пустые значения группируются под меткой `—`).
- Производит `LEFT JOIN` с подзапросом активности из `audit_log` за выбранный период (`created_at >= cutoff`), сгруппированным по пользователям.
- Считает общее число пользователей департамента (`total_users`), число пользователей с `last_login_at >= cutoff` (`active_users`) и сумму совершенных событий аудита (`events`). Сортировка: сначала по числу активных сотрудников (`active_users DESC`), затем по общему числу сотрудников в отделе (`total_users DESC`).

## 4. Frontend

Вся визуализация админ-аналитики сосредоточена в компоненте `./frontend/src/pages/admin/tabs/AnalyticsTab.vue`.

- **Интеграция с TanStack Query**:
  Фронтенд использует преднастроенные хуки запросов из `./frontend/src/queries/admin.ts` со значением `staleTime: 60_000` (1 минута):
  - `useAnalyticsDashboardQuery()`
  - `useAnalyticsTopArticlesQuery()` — жестко запрашивает топ-10 (`limit = 10`) за последние 30 дней.
  - `useAnalyticsTopNewsQuery()` — запрашивает топ-10 (`limit = 10`) за последние 30 дней.
  - `useAnalyticsTopFilesQuery()` — запрашивает топ-10 (`limit = 10`) за последние 30 дней.
  - `useAnalyticsDepartmentsQuery()` — запрашивает данные за последние 30 дней.
- **Интерфейс вкладки**:
  1. **Панель управления**: Отображает время последней генерации данных на сервере и предоставляет кнопку «Обновить», которая вызывает `invalidateQueries` по ключу `['admin', 'analytics']` для сброса кэша и мгновенного запроса актуальных данных.
  2. **Сетка KPI (kpi-grid)**: Рендерит карточки ключевых показателей эффективности (пользователи, контент, активность входов и действий за 24 часа/30 дней).
  3. **Графики-спарклайны (sparklines)**: Кастомные мини-графики на чистом HTML/CSS для визуализации тренда входов и публикаций за 14 дней. Высота баров рассчитывается динамически относительно максимального значения выборки.
  4. **Таблицы данных (series-card)**: Четыре параллельные таблицы (`n-data-table` из Naive UI), отображающие:
     - Топ статей KB (Дата обновления, Раздел, Название, Просмотры).
     - Топ новостей (Название, Дата публикации, Просмотры).
     - Топ скачиваний файлов (ID, Название ресурса, Последнее скачивание, Количество скачиваний).
     - Активность по отделам (Отдел, Всего сотрудников, Активные сотрудники, Количество событий).

## 5. Особенности и нюансы

- **Масштабируемость**: Вычисление метрик на лету является полностью достаточным для целевого масштаба в ~300 конкурентных сессий и периода хранения логов в 12 месяцев. На больших объемах данных рекомендуется перенос тяжелых группировок (особенно по таблице `audit_log`) на материализованные представления PostgreSQL.
- **Реалтайм-активность за час**: Дашборд определяет активных пользователей за последний час по записям в `audit_log`, а не по полю `last_login_at` в таблице `users`. Это позволяет видеть точную картину текущей вовлеченности в реальном времени.
- **Удаленный контент**: Счётчики опубликованного контента (новости и статьи KB) строго проверяют условие `deleted_at IS NULL`, чтобы исключить влияние удаленных материалов на статистику.
- **Историчность скачиваний файлов**: В отличие от контента, топ скачиваний файлов строится исключительно по записям `audit_log`. Даже если сам файл или фото были удалены, статистика их прошлых скачиваний сохраняется в отчете.
- **Расхождения лимитов бэкенда и фронтенда**: Бэкенд-эндпойнты по умолчанию возвращают `limit=20` записей, но фронтенд в TanStack-квери переопределяет этот параметр, запрашивая только топ-10 (`limit=10`) для оптимизации высоты интерфейса и уменьшения нагрузки на сеть.
