# Модуль «Аналитика»

> **Когда читать:** админ-аналитика, дашборд, статистика просмотров, активность отделов, популярные файлы.
> **Ключевой код:** `./backend/app/api/analytics.py`, `./backend/app/services/analytics_repo.py`, `./backend/app/schemas/analytics.py`, `./frontend/src/api/analytics.ts`, `./frontend/src/pages/admin/tabs/AnalyticsTab.vue`.
> **ADR:** —. **См. также:** `./docs/audit.md`, `./docs/api-contracts.md`.

> Собственный модуль портала для администраторов (Read-Only). Позволяет в реальном времени отслеживать ключевые метрики использования интранет-портала, вовлеченность пользователей, публикационную активность, наиболее просматриваемый контент (новости, статьи Базы Знаний), популярные файлы для скачивания и уровень активности различных отделов организации. Все агрегации выполняются "на лету" (on-demand) прямыми SQL-запросами к PostgreSQL.

## 1. Обзор

| Аспект | Значение |
|---|---|
| Backend | FastAPI (`./backend/app/api/analytics.py`), SQLAlchemy, PostgreSQL (on-demand агрегация) |
| Frontend | Vue 3 + Naive UI + TanStack Query (`./frontend/src/pages/admin/tabs/AnalyticsTab.vue`, `./frontend/src/api/analytics.ts`) |
| Воркер | Отсутствует |
| Хранилище | Только БД (PostgreSQL) |
| Префикс API | `/api/v1/analytics` |
| ACL-кэш | Отсутствует (кэширование только на стороне клиента в TanStack Query, `staleTime: 60_000` мс) |

### Возможности

- **Селектор периода (7/30/90/365 дней)**: единый переключатель на вкладке драйвит `days` всех period-зависимых запросов (top-*, departments, временные ряды dashboard, stale-content, feedback, drill-down). KPI-окна с фиксированным определением («за 30 дн.», «за сутки», «за 1 ч») не зависят от селектора.
- **Сводный KPI-дашборд**: оперативные метрики по пользователям (всего, активные за 30 дней, активные за 1 час, новые за 30 дней), контенту, вовлечённости и активности.
- **Вовлечённость (WAU/MAU)**: число уникальных активных пользователей за 7 дней (WAU) и 30 дней (MAU) по `audit_log` (метрика активности, а не `last_login_at`).
- **Временные ряды (Sparklines)**: динамика за выбранный период по четырём рядам — входы пользователей, активные пользователи (distinct), публикации новостей и загрузки файлов.
- **Популярные статьи KB**: рейтинг опубликованных статей Базы Знаний по количеству просмотров с привязкой к разделам.
- **Популярные новости**: рейтинг опубликованных новостей по числу просмотров.
- **Топ скачиваний**: агрегация скачиваний и экспортов файлов из логов аудита за выбранный период.
- **Топ переходов по ярлыкам**: рейтинг корпоративных ярлыков по событию `links.visited`.
- **Застойный контент (контент-гигиена)**: статьи KB и новости с 0 просмотров либо давно не обновлявшиеся (по `updated_at`) — для чистки базы знаний.
- **Статистика обращений (feedback)**: счётчики по статусам (всего / открыто / в работе / закрыто) и среднее время первого ответа.
- **Drill-down по ресурсу**: при клике на строку в «Топ переходов» / «Топ скачиваний» строится sparkline ежедневной динамики событий по конкретному ярлыку/файлу.
- **Экспорт таблиц**: выгрузка любой таблицы аналитики в CSV (UTF-8 BOM) или XLSX (openpyxl).
- **Активность отделов**: распределение сотрудников, их сессионной активности и общего числа совершенных действий по департаментам.

## 3. Модель данных

Модуль не имеет собственных таблиц в базе данных. Вся аналитика строится на основе динамических SQL-запросов к таблицам других модулей:
- **`users`** — используется для подсчета общего, нового (за 30 дней) и активного числа пользователей, а также группировки по департаментам.
- **`audit_log`** — используется для подсчета активности за последний час (уникальные сессии), логинов и общего числа событий за последние 24 часа, построения тренда входов за 14 дней, топа скачиваний файлов и подсчета событий по отделам.
- **`news`** — используется для подсчета новых публикаций за 30 дней, построения тренда публикаций, рейтинга популярных новостей, а также для застойного контента.
- **`kb_articles`** — используется для подсчета новых статей базы знаний за 30 дней, рейтинга популярных статей и застойного контента.
- **`feedback` / `feedback_replies`** — используются для статистики обращений: счётчики по статусам и среднее время первого ответа (`MIN(feedback_replies.created_at) - feedback.created_at`).

Все таблицы, ключевые поля, внешние ключи и индексы описаны в `./docs/db-schema.md`.

## 4. Модель прав (ACL)

- Доступ ко всем эндпоинтам модуля «Аналитика» имеют **исключительно администраторы** портала.
- На стороне бэкенда доступ жестко контролируется зависимостью `AdminDep` во всех эндпоинтах роутера `./backend/app/api/analytics.py`.
- На стороне фронтенда вкладка `./frontend/src/pages/admin/tabs/AnalyticsTab.vue` отображается только пользователям с ролью администратора.
- Модуль работает исключительно в режиме **Read-Only** — в нем отсутствуют операции создания, изменения или удаления данных.

Подробнее см. матрицу ролей в `./docs/roles-matrix.md`.

## 6. Источники данных

Все данные рассчитываются динамически с помощью SQL-запросов (без промежуточного хранения агрегированных метрик в БД).

### 6.1. Сводный дашборд (`_SCALARS_SQL`)
- **Пользователи (`users`)**:
  - `total_users`: Общее число записей в таблице `users`.
  - `active_users_30d`: Количество пользователей с `last_login_at >= now - 30 days`.
  - `new_users_30d`: Количество пользователей с `created_at >= now - 30 days`.
  - `active_users_1h`: Количество уникальных `user_id` из `audit_log`, у которых зафиксирована активность за последний час (`created_at >= now - 1 hour`).
- **Контент (`news`, `kb_articles`)**:
  - `published_news_30d`: Количество новостей в статусе `published` с `published_at >= now - 30 days` и не находящихся в корзине (`deleted_at IS NULL`).
  - `published_articles_30d`: Количество статей базы знаний в статусе `published` с `published_at >= now - 30 days` and не находящихся в корзине (`deleted_at IS NULL`).
- **Активность (`audit_log`)**:
  - `audit_24h`: Общее количество записей в таблице `audit_log` за последние 24 часа.
  - `logins_24h`: Количество успешных авторизаций (`event_type = 'auth.login'`) за последние 24 часа.
  - `wau_7d`: Количество уникальных `user_id` из `audit_log` за последние 7 дней (Weekly Active Users).
  - `mau_30d`: Количество уникальных `user_id` из `audit_log` за последние 30 дней (Monthly Active Users).

### 6.2. Временные ряды (period-driven, фильтр `created_at/published_at >= now - days`)
Все четыре ряда группируются по `date_trunc('day', ...)::date` и управляются Query-параметром `days` эндпоинта `/dashboard` (по умолчанию 14). Имена полей в ответе (`daily_logins_14d`, `daily_publications_14d`) сохранены ради обратной совместимости, но окно теперь динамическое.
- **`daily_logins_14d`** (`_DAILY_LOGINS_SQL`): события `auth.login` из `audit_log`.
- **`daily_active_users`** (`_DAILY_ACTIVE_USERS_SQL`): `count(DISTINCT user_id)` из `audit_log` (тренд активных пользователей).
- **`daily_publications_14d`** (`_DAILY_PUBLICATIONS_SQL`): опубликованные и не удалённые новости по `published_at`.
- **`daily_uploads`** (`_DAILY_UPLOADS_SQL`): события загрузок (`files.file_uploaded`, `kb.file_upload`, `photos.photo_uploaded`) из `audit_log`.

### 6.3. Популярные статьи KB (`/api/v1/analytics/top-articles`)
- Выполняет `LEFT JOIN` между таблицами `kb_articles a` и `kb_sections s` по идентификатору секции `s.id = a.section_id`.
- Фильтрует статьи: `a.deleted_at IS NULL` (не удалена), `a.status = 'published'` (опубликована), и дата публикации или обновления попадает в заданный интервал (`a.published_at >= cutoff` или `a.updated_at >= cutoff`, либо дата публикации пуста).
- Данные сортируются по `a.view_count DESC, a.updated_at DESC`.

### 6.4. Популярные новости (`/api/v1/analytics/top-news`)
- Выбирает записи из таблицы `news`, фильтруя по `deleted_at IS NULL`, `status = 'published'` и `(published_at IS NULL OR published_at >= cutoff)`.
- Сортирует по `view_count DESC, published_at DESC NULLS LAST`.

### 6.5. Топ скачиваний файлов (`/api/v1/analytics/top-files`)
- Группирует записи таблицы `audit_log` по полю `resource_id` за период `created_at >= cutoff`.
- Отслеживает только события, входящие в перечень:
  - `files.file_downloaded` — скачивание файлов из общего хранилища.
  - `kb.file_download` — скачивание вложений статей Базы Знаний (имя файла в `metadata.filename`).
  - `photos.photo_downloaded` — скачивание оригиналов фотографий (`?download=true`).
  - `kb.article_exported_pdf` — экспорт статей Базы Знаний в PDF.
  - `kb.article_exported_docx` — экспорт статей Базы Знаний в DOCX.
- Для имени файла берётся `COALESCE(NULLIF(MAX(resource_title), ''), MAX(metadata->>'filename')) AS title` (часть событий пишет имя в `resource_title`, скачивание KB-вложений — в `metadata.filename`), суммирует количество скачиваний `count(*) AS downloads` и определяет дату последнего скачивания `MAX(created_at) AS last_download`. Сортировка выполняется по `downloads DESC`.

### 6.6. Топ переходов по ярлыкам (`/api/v1/analytics/top-links`)
- Группирует записи `audit_log` по `resource_id` за период `created_at >= cutoff`, отбирая только событие `links.visited`.
- Событие `links.visited` эмитится в `./backend/app/api/links.py`: для прямых (внешних/внутренних) ярлыков — эндпоинтом `POST /links/{link_id}/click` (вызывается фронтендом fire-and-forget), для SSO-ярлыков — серверно внутри `GET /links/{link_id}/sso-redirect` (двойного учёта нет, т.к. SSO всегда проходит через редирект-эндпоинт). `resource_title` = название ярлыка.
- Возвращает `MAX(resource_title) AS title`, `count(*) AS clicks`, `count(DISTINCT user_id) AS unique_users`, `MAX(created_at) AS last_click`. Сортировка по `clicks DESC, last_click DESC`.

### 6.7. Активность по отделам (`/api/v1/analytics/departments`)
- Формирует список уникальных департаментов на основе поля `department` из таблицы `users u` (пустые значения группируются под меткой `—`).
- Производит `LEFT JOIN` с подзапросом активности из `audit_log` за выбранный период (`created_at >= cutoff`), сгруппированным по пользователям.
- Считает общее число пользователей департамента (`total_users`), число пользователей с `last_login_at >= cutoff` (`active_users`) и сумму совершенных событий аудита (`events`). Сортировка: сначала по числу активных сотрудников (`active_users DESC`), затем по общему числу сотрудников в отделе (`total_users DESC`).

### 6.8. Застойный контент (`/api/v1/analytics/stale-content`)
- `UNION ALL` двух выборок: KB-статьи (`kind='kb'`) и новости (`kind='news'`), обе — `deleted_at IS NULL AND status='published'`.
- Условие застоя: `COALESCE(view_count, 0) = 0 OR updated_at < cutoff`.
- Сортировка: `view_count ASC, updated_at ASC` — наверху самое «застойное».

### 6.9. Статистика обращений (`/api/v1/analytics/feedback`)
- Считает по таблице `feedback` за период `created_at >= cutoff`: `total`, `open`, `in_progress`, `closed` (через `FILTER (WHERE status = ...)`).
- Среднее время первого ответа: `AVG(EXTRACT(EPOCH FROM (first_reply_at - f.created_at)))`, где `first_reply_at = MIN(feedback_replies.created_at)` (LEFT JOIN-подзапрос). Если ответов нет — `NULL`.

### 6.10. Динамика по ресурсу / drill-down (`/api/v1/analytics/resource-trend`)
- Ежедневная агрегация `audit_log` по фиксированному `resource_id` (bind-параметр) за `days`.
- `kind='link'` → событие `links.visited`; `kind='file'` → набор download/export-событий (`_DOWNLOAD_EVENTS`, тот же, что в топ-файлах). Имена событий подставляются как bind-параметры (без интерполяции).

### 6.11. Экспорт таблиц (`/api/v1/analytics/export`)
- Переиспользует repo-функции соответствующих таблиц через `_export_rows`; набор колонок и заголовки — в `_EXPORT_COLUMNS` (по `dataset`).
- **CSV**: stdlib `csv` + префикс UTF-8 BOM (`\ufeff`) для корректного открытия в Excel; `datetime` сериализуется в ISO.
- **XLSX**: `openpyxl` (как в модуле справочников), заголовок жирным, имя листа = `dataset[:31]`.

## 7. Особенности фронтенда

Визуализация админ-аналитики сосредоточена в компоненте `./frontend/src/pages/admin/tabs/AnalyticsTab.vue`.

- **Интеграция с TanStack Query**:
  Фронтенд использует преднастроенные хуки запросов из `./frontend/src/queries/admin.ts` со значением `staleTime: 60_000` (1 минута). Все хуки принимают реактивный аргумент `days` (`MaybeRefOrGetter<number>`), завязанный на селектор периода — `queryKey` включает `days`, поэтому смена периода автоматически перезапрашивает данные:
  - `useAnalyticsDashboardQuery(days)` — `days` влияет на временные ряды.
  - `useAnalyticsTopArticlesQuery(days)` / `useAnalyticsTopNewsQuery(days)` / `useAnalyticsTopFilesQuery(days)` / `useAnalyticsTopLinksQuery(days)` — топ-10 (`limit = 10`).
  - `useAnalyticsDepartmentsQuery(days)`.
  - `useAnalyticsStaleContentQuery(days)` — `limit = 20`.
  - `useAnalyticsFeedbackQuery(days)`.
  - `useAnalyticsResourceTrendQuery(kind, resourceId, days)` — `enabled` только при заданном `resourceId` (drill-down).
- **Интерфейс вкладки**:
  1. **Панель управления**: время последней генерации данных, селектор периода (`n-select`: 7/30/90/365) и кнопка «Обновить» (`invalidateQueries` по ключу `['admin', 'analytics']`).
  2. **Сетка KPI (kpi-grid)**: четыре карточки — Пользователи, Вовлечённость (WAU/MAU + публикации), Активность (события/входы за сутки), Обращения (счётчики статусов + среднее время ответа с человекочитаемым форматтером мин/ч/дн.).
  3. **Графики-спарклайны (sparklines)**: четыре ряда (входы, активные пользователи, публикации, загрузки) на чистом HTML/CSS; высота баров — относительно максимума выборки. Отдельная drill-down-карточка появляется при выборе ресурса (клик по строке топа ярлыков/файлов), кнопка «Закрыть» сбрасывает выбор.
  4. **Таблицы данных (series-card)**: шесть таблиц (`n-data-table`); у каждой в заголовке — меню экспорта (`n-dropdown` CSV/XLSX → `downloadExport`, скачивание через `<a>` с cookie-авторизацией). Гибким текстовым колонкам задан `minWidth`, числовым/датным — фиксированный `width`; сетка `.analytics-tables` использует `minmax(460px, 1fr)`:
     - Топ статей KB (Дата обновления, Раздел, Название, Просмотры).
     - Топ новостей (Название, Дата публикации, Просмотры).
     - Топ скачиваний файлов (Название, Последнее скачивание, Количество скачиваний) — клик по строке открывает drill-down; «сырая» колонка `resource_id` (UUID) убрана как неинформативная.
     - Топ переходов по ярлыкам (Название, Переходы, Уникальных, Последний переход) — клик по строке открывает drill-down.
     - Застойный контент (Тип, Название, Просмотры, Обновлено).
     - Активность по отделам (Отдел, Всего сотрудников, Активные сотрудники, Количество событий).

## 8. Нюансы реализации

- **Масштабируемость**: Вычисление метрик на лету является полностью достаточным для целевого масштаба в ~300 конкурентных сессий и периода хранения логов в 12 месяцев. На больших объемах данных рекомендуется перенос тяжелых группировок (особенно по таблице `audit_log`) на материализованные представления PostgreSQL.
- **Реалтайм-активность за час**: Дашборд определяет активных пользователей за последний час по записям в `audit_log`, а не по полю `last_login_at` в таблице `users`. Это позволяет видеть точную картину текущей вовлеченности в реальном времени.
- **Удаленный контент**: Счётчики опубликованного контента (новости и статьи KB) строго проверяют условие `deleted_at IS NULL`, чтобы исключить влияние удаленных материалов на статистику.
- **Историчность скачиваний файлов**: В отличие от контента, топ скачиваний файлов строится исключительно по записям `audit_log`. Даже если сам файл или фото были удалены, статистика их прошлых скачиваний сохраняется в отчете.
- **Расхождения лимитов бэкенда и фронтенда**: Бэкенд-эндпойнты по умолчанию возвращают `limit=20` записей, но фронтенд в TanStack-квери переопределяет этот параметр, запрашивая только топ-10 (`limit=10`) для оптимизации высоты интерфейса и уменьшения нагрузки на сеть.

## Безопасность

- **Ограничение доступа**: Все эндпоинты защищены с помощью зависимости `AdminDep`. Обычные пользователи или неавторизованные гости не могут получить доступ к этим данным (сервер возвращает HTTP 403 Forbidden).
- **Защита от SQL-инъекций**: Все SQL-запросы используют безопасную параметризацию (через SQLAlchemy `text()` и параметры `:cutoff`, `:limit`).
- **Минимизация привилегий**: Модуль работает исключительно в режиме Read-Only (не принимает никаких POST/PUT/DELETE запросов и не изменяет состояние базы данных).
- **Защита персональных данных**: Чувствительные данные (пароли, токены сессий) не запрашиваются и не выводятся в API. Метрики по пользователям включают только обезличенные агрегаты или общедоступную информацию (имя, департамент, дата последнего входа).

## События аудита

- Модуль работает исключительно в режиме чтения и сам по себе не генерирует новые события аудита (`push_audit_event` не вызывается).
- Тем не менее, он активно использует (агрегирует) события аудита из таблицы `audit_log` для построения отчетов по входам пользователей и скачиванию файлов.
