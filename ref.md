## 0. Принципы (не меняем)

- Рефакторинг **не меняет поведение**: контракт API (`openapi.json`), UI и тесты остаются прежними.
- Любой шаг начинается и заканчивается **зелёным baseline** (см. этап 2).
- Один вид изменения = один коммит/PR. Не смешивать с багфиксами и фичами.
- Трогаем то, что покрыто тестами. Нет покрытия — сначала характеризующий тест, потом правка.
- Приоритет целей = **размер × частота изменений** (где реальная боль).

## 4. Качественный анализ кандидатов

Для каждого файла из топ-матрицы — короткий разбор (заполняется по ходу):

- **Запахи**: длинные функции, дублирование, смешение слоёв (логика в хендлерах/компонентах), магические числа, мёртвый код.
- **Слои**: backend — толстые `api/*` вместо `services/*`; frontend — толстые `.vue` вместо `composables/*`.
- **Типы**: модули вне strict-списка `mypy` (`pyproject.toml`), `any`/нетипизированное на фронте.
- **Технический долг в конфиге**: `per-file-ignores` в `ruff` (есть `TODO(REVIEW-5.2)`), отключённые правила.
